直接查询 PostgreSQL 可使用 [批量查询示例](批量查询示例.sql)，其中区分已知事件数和包含未知项的固定槽位总数。

游戏经过根据各局转写补充；座位姓名根据用户授权读取原视频姓名牌，按用户确认的“同日座位相同”规则复用到当天各局。当前47日149局的12座姓名全部齐全，共1788个座位，画面待核项为0；文字疑点仍有待复核，按实际记录继续处理。工作台保留来源截图、时间和画面 ID。[入库一致性验收](../../reports/S22_对局批处理验收.json) 记录数据库、逐局档案、示例文件及复核链接的检查结果；这是结构与存储检查，不代替你确认事实。

每局目录按日期、局次和 BVID 命名。常用文件是 `复核.html`、`复核.md`、`dossier.json`、`复盘原文.txt`、`复盘定位.json`、`复核记录.json`、`database_receipt.json`、`座位身份.csv` 和 `游戏事件.csv`。没有集中复盘但有候选定位时，还会有 `定位上下文.txt`。

批量进度保存在[进度 JSON](../../../data/reports/S22_对局批处理进度.json)，逐步记录保存在[日志 JSONL](../../../data/reports/S22_对局批处理日志.jsonl)；备份路径记录在进度 JSON 的 `backup` 字段，备份文件位于 `data/backups/`。要继续时在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe scripts\batch_s22.py status
.\.venv\Scripts\python.exe scripts\s22_text_review.py status
.\.venv\Scripts\python.exe scripts\s22_review_server.py
```

文字补充的续接位置和剩余数量见 [逐句核对进度](../../reports/S22_转写逐句复核进度.json)；工作台保存的疑点结论见各局 `复核记录.json`。

“已入库待复核”不是人工确认。`unknown` 也不表示空过、弃票或平民。只有对照原文检查完成后，才按操作文档中的步骤重新入库修正项并标记复核完成。版型细则见 [S22 版型规则与夜间顺序](../../../docs/10_版型规则与夜间顺序.md)。
