复核范围为官方《昆仑归墟》合集当前归档的75局正赛，日期为2026-09-08至2026-10-16。12局表演赛不建立对局候选，不纳入复核与统计；已有原始媒体归档保留。

打开 [S23逐局推导与复核页](../data/exports/S23_逐局推导与复核.html)。页面按比赛日期、核实后的局次排序，提供实际底牌与座位姓名、逐夜行动、逐日事件、警徽票、放逐票、悍跳判断、独立拍刀、截图和最终复盘带时间戳转写。左侧可以搜索日期、版型、姓名或BV号，也可以筛选需要用户亲自核对的对局。实际完成数量及问题数量以 [生成进度](../data/reports/S23_逐局复核进度.json) 为准。

2026-10-26 逐日核查：75局均已依据最终复盘核对，疑点结合完整转写、前后流程与必要画面交叉核查。当前只有1项需要用户决定的遗言诈身份统计口径，另9条节目未公开的信息记录单列资料限制、继续保留未知。左侧选择“需要你亲自核对”可直接定位；详见 [本轮交付](../data/reports/S23_逐日复核交付_20261026.md) 与 [个人清单](../data/exports/S23_必须人工复核.csv)。页面时间戳转写仅保留最后复盘，原始全文未删除。

## 复核与反馈

1. 查看本局候选及推导依据。点击原文旁的“听这一段”播放本地音频，或通过“视频定位”打开B站对应时间；底牌依据中的画面可单独打开。
2. 对具体问题填写结论与依据，并在“本局复核意见”选择同意、更正或仍不确定。没有单独人工问题的对局仍未自动视为用户确认。
3. 点击页首“导出我的复核意见”，保存JSON文件并交回。页面也支持导入同一候选快照的意见文件。

意见暂存在当前浏览器的本地存储中。更换浏览器或清理浏览数据前应导出。导入时校验候选快照、原文SHA256和候选档案SHA256，版本不匹配时拒绝覆盖。HTML引用同项目下的音频与截图，单独复制HTML不能带走这些媒体文件。

## 口径与证据

沿用 [S22正式录入口径](12_S22正式版型规则与录入流程.md)、[投票复核口径](13_S22逐日投票与警下名单.md) 和网站 `website/api/bluffs.py` 的悍跳定义。原话、AI推断、用户确认分别保存。

- 底牌使用裁判复盘和可见实际身份栏核对；黄色自称、解说推测及票型标注不能代替底牌。姓名采用已经确认的S23微博人名映射，并记录截图补正或同日同阵容的复用依据。
- 复盘的角色词修饰后面的座位号码，不能在跨字幕行时误挪给前一座位。日序使用自爆、入夜、死亡公布、放逐与后续行动交叉重建，明确记录复盘口误。
- “警长归票甲乙PK”可能是双归票。只有实际首轮平票后再次投票，才建立独立PK票轮。首轮平票后直接拍刀或交牌的，不补造PK复投。
- 逐人票表只显示投票者与投向。狼混按胜利阵营计入狼方；狼人方可用票数大于等于好人方时满足绑票条件，警长半票必须计入持徽者阵营。理论票力与实际投票分别保存，不据理论条件删除后续现场流程。
- 同一已确认票轮内，票权能唯一重建时补齐票权；未播报投向者按现有用户口径默认弃票，并注明推导依据。整轮未找到时不把所有人自动记弃票。
- 首夜死者可能在竞选结束后才被宣布死亡；延期竞选中吞毒自爆也不能据此把毒药挪到另一夜。
- 狼人悍跳需要实际狼人底牌及公开自称预言家或通灵师的归属证据。拿徽、上警或被复盘称为“悍跳狼”不能替代所跳身份核查；狼混按既有物理身份口径单列。遗言自称等既有定义未明确覆盖的边界另列具体问题。
- 拍刀独立保存，明确目标为集合，不代表刀序或全部有效死者。普通夜刀和讨论中的假设拍刀不混入。

新增青丘夜影、魔幻对决的本季现场结算依据见 [S23案例规则](../config/S23_review_rules.json)。该文件记录当局已发生的结算，不宣称完整覆盖新版型所有技能边界。候选中的新版型事件保留明确技能字段，正式导入前仍需与版型登记册及数据库枚举核对。

## 文件与数据库边界

每局原始提取、AI逐局复核和主审补正位于 `data/extractions/S23/game_reviews/{BVID}/`。`entry.json`绑定原字幕或全文转写的路径与SHA256；`baseline.*`只是机器起点，不能当作最终结论。`dossier.reviewed.json`、`voting.reviewed.json`、`ai_review.json`保存逐局判断，`primary_review.json`记录此前主审补正；`daily_audit.json`记录本轮逐日审计、复盘窗口、事件补丁、逐项结论和原句哈希。原始reviewed文件保留，生成时应用审计补丁。资料未公开用not_observed记录，不伪装成confirmed，也不自动增加用户任务。

汇总候选位于 `data/games/S23/{日期}_g{局次}_{BVID}/`：

| 文件 | 用途 |
| --- | --- |
| `dossier.candidate.json` | 座位、底牌、胜负及逐轮事件 |
| `voting.candidate.json` | 报名、逐轮警徽票与放逐票、日覆盖 |
| `endgame.candidate.json` | 独立拍刀阶段及原文证据 |
| `vote_control.candidate.json` | 狼混阵营可用票数、警徽与实际票轮是否存在 |
| `supplemental.candidate.json` | 现有固定槽未覆盖的DQ、交牌等额外现场观察 |
| `ai_review.json` | 字段修正、悍跳推导、证据与人工问题 |

动作别名、机械狼形态名称、固定槽顺序和每日覆盖枚举由 `scripts/s23_schema.py` 整理，变更前后值见 [结构规范化依据](../data/reports/S23_结构规范化依据.json)。混血榜样保存在专属事件中，不能占用机械狼学习字段。现有槽无法表达的观察单独保留，不丢失，也不冒充一次普通技能。原始AI逐局JSON不被结构整理覆盖。

本轮只写候选文件和复核页面，不写正式对局表，也不发布到网站。原始媒体、字幕登记属于此前资料采集阶段。用户复核后再制定可重放的接受记录、检查新版型格式并导入正式数据库。


数据校验检查75局正赛范围、来源绑定、座位与角色组成、行动目标、药量、投票ID及原文时间窗。页面验收逐局打开并核对12个座位，验证本地来源链接、反馈暂存、导入导出、错误快照拒绝和390像素窄屏布局。程序检查通过不等同于用户确认事实。

盗宝大师首夜狼刀使用forbidden且无目标；不混作主动pass。明确的现场终局播报优先限定展示边界，保存理论重放结果作对照。未宣布死亡的首夜玩家实际警下票与后续放逐票权分别检查。
