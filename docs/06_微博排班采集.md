## 登录态

微博需要自己的 Cookie，不能复用 B 站 Cookie。已有 `.secrets/weibo.cookies.txt` 时直接采集即可。

首次导出时，在现有 Chrome 正常登录微博，并打开一次 `https://m.weibo.cn/` 确认移动端也已登录。在 `chrome://inspect/#remote-debugging` 开启远程调试后，使用 Chrome 提供的本机端点；例如：

```powershell
.\.venv\Scripts\python.exe scripts/login_session.py weibo --cdp-url ws://127.0.0.1:9222/devtools/browser
```

若 Chrome 提供旧式 HTTP 端点，可将地址换成 `http://127.0.0.1:9222`。脚本只导出影响微博域的 Cookie，保存到 `.secrets/weibo.cookies.txt`，不打印 Cookie 值。连接现有 Chrome 时不创建标签页、不导航页面、不关闭浏览器；Chrome 自身弹出的连接确认需在浏览器中完成。

## 最初的最近一个月样本

```powershell
.\.venv\Scripts\python.exe scripts/collect_weibo.py --uid 7525583841 --since 2026-09-20 --until 2026-10-20 --max-pages 50 --auth cookies --cookies-file .secrets/weibo.cookies.txt --download-images --expand-long-text
```

本轮不传 `--keyword`，保留窗口内全部可见帖子，避免漏掉正文未写“排班”、信息只在图片里的公告。每次请求至少间隔一秒；只保存帖子与配图，不下载视频、评论。

原件在 `data/raw/weibo/<本次采集目录>/`，包含 `manifest.json`、`posts/` 原始帖子对象，以及 `images/` 配图。`manifest.json` 记录正文、作者、发帖日期、原帖链接、每页计数、图片哈希和采集终止原因。

移动列表里的长文可能截成“……全文”。`--expand-long-text` 通过微博的长文接口补齐，原列表响应仍保留在 `posts/`，完整响应另存 `long_text/`，清单记录 `full_text_file` 与 `full_text_status`。中断后可单独补取已有清单，复用成功保存的长文响应：

```powershell
.\.venv\Scripts\python.exe scripts/collect_weibo.py --expand-manifest data/raw/weibo/<本次采集目录>/manifest.json --auth cookies --cookies-file .secrets/weibo.cookies.txt
```
