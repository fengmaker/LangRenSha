## 第2步：确定独立日期窗口，复用微博登录态

**具体操作**：按目标季实际赛期分月或分段向前采集。每个新窗口独立存放；相同窗口续跑使用原目录和manifest，不能修改旧窗口日期后接旧游标。`--since`、`--until`均含当天，按发帖北京时间筛选；正文比赛日期另行提取。

复用`.secrets/weibo.cookies.txt`。微博与B站登录态分开，凭据不写进文档或日志。首次／过期时在正常Chrome登录微博并打开一次`https://m.weibo.cn/`确认移动端登录；需要重新导出时，在`chrome://inspect/#remote-debugging`启用调试，传入Chrome显示的实际完整端点：

```powershell
.\.venv\Scripts\python.exe scripts/login_session.py weibo --cdp-url <Chrome提供的完整本机端点>
```

连接现有Chrome不新建标签、不导航、不关闭浏览器，Chrome自身的连接确认在浏览器完成。

**产物／验收**：新窗口的UID、起止日期和目录对应，登录可正常访问官方时间线。出现验证、限流或登录要求即保存进度停止，不循环请求；零结果不能直接解释为该月没有帖子。

## 第3步：向前采集全部帖子、完整长文和配图

下面保留从原有边界补**2026-05-01—05-25**的命令示例；该日期段现已包含在2026-02-24至2026-05-26新增原件窗口中，无需重复执行。后续实际按目标季赛期设置尚未采集的日期，完成示例窗口不等于找全更早赛季。

```powershell
.\.venv\Scripts\python.exe scripts/collect_weibo_archive.py --since 2026-05-01 --until 2026-05-25 --request-interval 1.5 --max-pages 300
```

默认新目录为`data/raw/weibo/2026-05-01_2026-05-25_京城大师赛_UID7525583841/`。更早月份依次建立自己的窗口；可以传`--archive-dir`指定独立目录，传`--seed-manifest <旧manifest实际路径>`复用新窗口内已有帖子。跨窗口用原帖ID和图像SHA去重，保留所有引用。

**具体操作与产物**：

1. 不传关键词过滤，保留窗口内全部官方可见帖，避免遗漏信息只在图片里的公告。单连接顺序采集，每请求至少间隔1.5秒。
2. `posts/`保存原帖；长文补齐响应存`long_text/`。移动列表只给前九图而`pic_num`声明更多时，读取正常详情接口，保存`details/`并按原帖顺序补图。
3. `images/`保存原字节、大小和SHA256；已有合格文件复用，缺失／损坏才补取。`pages/`保存每页原件、日期范围和游标，manifest持续落盘。
4. 同命令续跑复用文件并从最后完整页游标继续。连续三个完整页面均早于起始日期才结束窗口，避免置顶旧帖提前截断。

现有命名示例：

```text
posts/2026-09/2026-09-22_15-30-56_S23_第03期_阵容公告__WB5345970930844085.帖子原始.json
long_text/2026-09/2026-09-22_15-30-56_S23_第03期_阵容公告__WB5345970930844085.长文原始.json
images/2026-09/2026-09-22_15-30-56_S23_第03期_阵容公告__WB5345970930844085_图01.jpg
details/2026-09/2026-09-22_15-30-56_S23_第03期_阵容公告__WB5345970930844085.详情原始.json
```

时间前缀是发帖北京时间，季期只取原文明示信息，未知保留待核；原帖ID区分同秒同标题。新窗口的命名季期解析若不适配目标历史季，先适配再批量，不能按日期猜季期。

**验收标准**：`window_scan_status=completed`且终止原因合理，长文和配图齐全。`partial`、页数上限、重复／缺失游标或验证／登录失败都不算完成。已完成窗口重跑不会自动刷新新帖；新增日期使用新窗口。扫描完成只覆盖可见窗口，不承诺恢复删除／不可见内容。


**具体操作**：核对作者、日期、命名、原帖／完整长文／详情／分页关联及每张图的大小和SHA256。导出比赛日、季期、阶段、选手、解说、法官和板子，保留正文原件及图片引用；原窗口不覆盖。

**产物**：`微博原件目录.csv`、采集验收、`微博整理.md`、`全部微博.csv`、`比赛排班.csv`。

**验收标准**：原件报告通过且没有未解释的错误／警告；目标季公告能被提取，不支持的历史写法先适配并用真实帖子核对。转发、图片公告、名单缺项和日期矛盾保留待核；解说／法官不混进选手，表演／娱乐／资格赛不混进正式范围。名单顺序不是座位号，板子列表不是每局实际配置。

## 第5步：为新图建立来源索引并识读名牌

**具体操作**：

1. 根据目标季排班原图按SHA256去重，保留全部原帖引用；同原图可复用既有识读和确认，不能丢掉新的出现日期。
2. 每图记录照片编号、赛季、`image_sha256`、`source_image`、名牌`crop_file`和裁剪区域；编号在批内唯一，跨批用窗口／编号及SHA关联，不能让两个P0001相互覆盖。
3. 每次引用保存原帖ID/URL、比赛日、阶段、原帖图片序号／路径、正文选手／解说／法官名单。
4. 原图保留，名牌裁图另存；按图上文字逐图读取候选姓名，标清清楚、存疑或无法辨认及理由。不根据人脸猜姓名，不按正文顺序配照片。

**产物**：新批次来源索引、名牌裁图、识读记录、候选表和复核页。

现有`build_weibo_name_review.py`只读取**已经准备好的**索引、裁图和`S22_A.json`／`S22_B.json`／`S23.json`等识读记录；它不会自动为新窗口编制索引或识别人名。新季先建立独立输入、适配读取器，再生成页面，不能仅改路径宣称完成。重新生成候选会重置初始CSV，已有确认文件保持原件。

**验收标准**：编号无重复，原图／裁图存在，排班配图引用全部覆盖，每次引用的原帖、图片序号及SHA一致；缺失的第10—12张图已经补齐。每条候选能回原图，存疑保留存疑。

## 第6步：确认新增姓名、别名和同季照片

**具体操作**：以已有规范人名为起点，逐图核新增名牌及别名。直接观察、推断、用户确认和未知分别保存；已经有明确依据的结论直接处理，有多解再问具体问题，不重复索取旧确认。

已确认原图可复用确认记录；同名但不同原图不能只凭名字相同就确认该照片。英文大小写按证据保留，同名异人分开，别名归并有来源。导出每人名单和逐图映射，保留原候选、修正值、依据和状态。

**产物**：新季规范姓名表、逐照片映射、确认来源及未决项；每条映射连接“赛季／姓名／照片编号／SHA／原帖／确认依据”。新增未知项只挂在新资料上，不重新打开已定案旧资料。

**验收标准**：确认编号覆盖相应候选、SHA／赛季一致，无冲突归并；同一确认结果能追到所有原帖。排班名单与正式上场人数分开，排班日数不能当对局数。

现有`export_reviewed_weibo_roster.py`包含本批S22/S23文件名、截至日期和“仅7月3日娱乐赛出现一次”的排除规则。新季先适配自己的范围，不照搬历史个案；`website/prepare_photos.py`也仍使用固定S22/S23输入，新季照片需适配后再生成。

## 第7步：核实际座位，建立座位→姓名→照片

**具体操作**：从新季录像首局介绍、本局姓名牌、法官点名或自我介绍确定实际座位，与微博名牌及规范姓名互证。微博明确写座位时保留原文／图号，再与现场核对。现场有换人、缺席或换座时采用实际出场并保留公告差异。

每条座位旁证保存目标季、对局ID、BV/CID/P、座位、规范姓名、原句／截图、原媒体时点和SHA。跨局复用注明来源局及未换人换座的依据。参考结构为S22的`data/extractions/S22/frame_seats/{BVID}.json`与S23的`data/extractions/S23/game_reviews/{BVID}/`，新季先定义并适配自己的格式。

**产物**：逐局座位—规范姓名及来源，连接对应同季照片；提交到新季复核及正式档案，既有赛季保持。

**验收标准**：已确定座位无重复或冲突，有现场证据，名字和照片来源可追溯。**正文名单顺序、原帖图片顺序都不能推出座位。**仍缺证据的新增座位留未知，不靠照片覆盖齐全推定座位已确认。

## 第8步：生成网站照片，随新季发布验收

**具体操作**：从新季正式座位的规范姓名计算实际目标，选择同季有确认依据的原图，按`{season}/{SHA256}.jpg`保存网站资产，写入照片清单；有可靠别名证据时保留别名链。旧季照片清单和已选图片保留。

**产物**：`website/api/player_photos.json`、`website/assets/player-photos/{season}/`、本季目标姓名／覆盖／缺图报告。

**验收标准**：每张网站照片能回到同季确认原图、来源日期／URL和SHA；别名证据完整，缺图有原因，不拿别季照片凑齐。清单变化后重启API清缓存，再按[15 发布与验收](15_赛季数据全流程操作手册.md)核全部保留季。
