# 通用规则推导

现有正式档案可直接生成前置推导，默认只写派生旁证，不改源字幕或核实记录：

```powershell
.\.venv\Scripts\python.exe scripts/prepare_game_rules.py --season S21 S22 S23 --apply --report data/reports/shared/S21_S22_S23_通用规则推导_20261029.json
```

省略`--apply`只预览；加`--bvid BV...`可限定对局。新建正式档案由各季适配器自动推导并保存；`workflow --stage publish`会先刷新旁证，再发布快照。只有明确要替换已有规范化JSON时才加`--materialize`。该命令不写数据库、不发布网站，也不表示对全部来源重新逐局核实。

本文说明如何在生成逐局规则推导时复用已确认的基础事实和同版型能力，并把推导与原始事实分开。**本轮用户明确确认：基础规则通用；同一版型的能力跨季共用；只有有证据的实际改版才形成覆盖。**因此，S21 配置没重复抄录一条规则，不等于该规则在 S21 失效；规则出处的赛季、配置当前是否完整，与规则本身的适用范围是两件事。

适用判断按以下优先级：

1. 已确认的基础角色规则，按实际身份应用于出现该身份的对局。
2. 已确认的版型能力，按实际版型跨季复用；同名、改标题、存档模板缺字段本身不构成改版。
3. 有直接证据的角色替换、人数/牌池变化、技能触发或结算修订，才对受影响字段设置版本差异。局部修订只覆盖相应能力，不重置同板其他规则。
4. 实际版型、身份、时点、存活、资源、目标映射或直接证据不能唯一确定时，保持未知/冲突，不能拿常见玩法补齐。

当前配置入口：[`game_rules.json`](../config/game_rules.json)集中维护基础规则、版型能力、案例与计分；[`seasons.json`](../config/seasons.json)保存实际范围、轮换及导入设置；[`board_templates`](../config/board_templates/README.md)每版型一份模板。来源完备度保存在`boards.*.evidence_records`，不因某季原资料缺项否定共同规则。案例仍按各自`status`和`scope`读取，单局裁定不因同板而自动泛化。

## 推导协议

| 基础事实前提 | 可推导状态 | 必须回证据或保留未知 |
|---|---|---|
| 本局版型与物理底牌已确认，适用的基础/同板规则已选定 | 固定事件槽的行动者角色、该时点可用技能、配置明确的合法动作与目标限制 | 实际玩家是否行动、选了谁、收到什么反馈；规则只给资格，不会证明该局发生了动作 |
| 已知按时点发生的离场、资源使用、学习/附加状态变化 | 后续存活、技能资格、资源余额、投票资格；可计算时给出可行目标集合 | 缺失/冲突的离场、目标身份、资源是否真的消耗；不得把unknown当成活着、未用或pass |
| 能力的原目标和变换规则均已确认，且映射唯一 | 变换后的实际目标、命中对象或目标映射 | 多个交换/保护/免疫作用无法唯一排序时，实际目标、死亡原因及其优先级 |
| 投票环节、当时存活名单、身份阵营、警徽状态与规则已确认 | 当轮有资格投票者、合法候选、弃票状态（仅限用户确认的“已建立票局但无明确投向”）、票力/绑票条件 | 漏失的投票名单、选票或轮次；理论绑票条件不能代替法官宣布胜方 |
| 终局条件、触发事件及结算先后已确认 | 终局发生时点；终局后的槽位标记不可用或不创建后续轮 | 终局条件本身证据不足、同一时点多效果顺序不明时，不能宣告胜方或补造后续行动 |

推导记录应引用规则键、输入事实及原始事件槽，写明状态、不可用原因、合法目标集合、资源前后值、存活/票权快照和冲突/待补证据。它是可复核的规则派生层，不是现场证据，也不是“事件已发生”的结论。可记录`available`、`locked`、`dead`、`spent`、`wrong_phase`、`unavailable`、`unknown`等语义，但序列化值遵从具体模板和消费者，不能强制跨季同枚举。

实现入口：`scripts/game_derivations.py::derive_game`生成存活、票权和逐槽状态；`scripts/role_constraints.py::event_constraint`计算角色资源、解锁和合法目标；`scripts/board_outcomes.py::derive_board_outcomes`计算特殊版型的可证实约束；`scripts/game_inference.py`复用已有毒药、猎人、交换及查验推导。三个赛季在正式校验和入库前调用，推导旁证保存为`rule_derivations.json`。规范化事件槽可以物化确定的规则状态，原始字幕、核实记录和候选证据不改。

## 警长报名证据的优先级

`sheriff_speech_evidence.load_bound_sheriff_speeches`只在报名名单缺失时补证据，按以下顺序执行：

1. `voting.registrations`已有第一天的完整上警/警下名单：直接使用，跳过字幕读取和发言轮分析。
2. 缺名单时，先复用`voting_records.find_registration_candidates`提取法官明确报出的报名名单；同一分钟内的更正以最后一次为准，保留原句与时间戳。有直接名单就跳过发言轮分析。
3. 直接名单仍缺失，才检查“报名口令→警上初始发言顺序→逐人正式点名→退水/警下投票”的窗口，保存观察到的座位及中断、漏句和号码冲突。即使流程起止完整，ASR仍可能漏掉点名；发言轮只留补充待核旁证，不自动补警下名单或票权。

不按整局视频中的发言次数判报名；PK、遗言、普通白天发言、复盘及退水后追加发言不混入初始轮。初始报名不等于最终竞选候选。由法官直接名单补出的报名先进入通用推导，再用于警下票权和漏票任务。发言轮旁证的`procedural_complete`仅表示流程起止连贯，不证明所有人的点名都已被字幕收录，`complete=false`且`off_police=null`。旁证保存在`rule_derivations.json.sheriff_speech_evidence`，包含选择方法、原句时间戳和字幕SHA；发布只核验并消费已算结果，不重跑解析。

## 查验与狼刀的身份约束

预言家/通灵师按实际版型核验行动身份、夜间阶段、单个目标及行动前已确认的离场；允许再次查验同一目标。目标缺失仍是待查，不记作已经违规。同夜才死亡的人保留当夜行动窗口，不能拿天亮公布的夜死名单提前清空当夜查验。

普通狼刀的目标范围不依赖是否记录了具体执行者：集体狼刀的`actor=null`仍可排除此前已离场的目标，但具体持刀资格保持未知。混血儿即使跟狼方获胜，也不因胜利阵营成为狼队成员。机械狼接普通刀依赖普通狼全离场，与学习的技能分开；其模仿的查验/守护/毒写入`mechanical_action`，保留原通灵师/守卫/女巫的独立槽位。

机械狼带刀确认在每夜开始时检查：首夜不带刀；后续仅在机械狼仍在场、其余普通狼人均已确认出局时，展示“已接过狼刀”。未带刀、无法发动或出局记录未知时隐藏该展示槽，白天不显示；S21/S22/S23共用此规则，旧档案未设此槽时也按已确认出局记录生成展示。

该版型没有复活机制。某普通狼人若在本夜或后续轮次才实际自爆、被放逐、夜间出局或被开枪带走，可反证其在本夜开始前尚未出局，从而排除机械狼接刀及双刀技能。只作为狼刀/技能的目标不等于实际出局，不能用来作此推断。

## 保持dossier与派生层分离

- `dossier.json`继续保存固定槽中的归档事实、证据支持的动作和结算；字段含义及其现有模板不改。原始音频/视频/字幕/规则图及SHA保持原样。
- 前置`rule_derivations.json`保存推导旁证：按`round/phase/slot`引用基础事实，记录规范化字段的before/after、规则与依赖。新建/重建正式档案时可将确定状态写入typed字段；已有档案也可只生成旁证，由导入/发布消费预计算补丁。原始字幕与核实记录不变。基础事实修改后先撤销仍与旧输出相同的派生值，再重新计算，避免旧的“不可用”残留。
- 对未观察事件，派生层可说明“按规则本应 unavailable / 尚未解锁 / 资格未知 / 可选合法目标集合”；不能伪装成现场`pass`、已行动或实际出局。
- 任何结论若依赖实际狼刀目标、交换顺序、毒药反弹、多重死亡先后或法官的临场裁定，而现有规则不能唯一求解，就保存规则条件和候选结果并回到具体证据；不扩成通用裁判引擎。
- 修改规则来源时，记录适用赛季/版型/身份/生效时点及覆盖字段。基础能力的来源季与适用季不同并不冲突；真实改版与单局特判仅覆盖明确范围。
