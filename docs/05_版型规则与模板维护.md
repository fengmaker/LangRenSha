# 版型规则与模板维护

先固定赛季、实际版型和正式范围，再查该季规则。相同版型名称不保证跨季技能、首夜、票权或结算相同；规则研究、现场裁定、用户确认与机器可执行约束各自注明来源和作用域。

## 规则入口

| 入口 | 用途与边界 |
| --- | --- |
| [赛季注册表](../config/seasons.json) | 运行期来源、范围／规则路径与实际适配入口；注册一行不等于已支持该季全部玩法 |
| `config/{season}_game_scope.json` | 正式／表演／娱乐范围、固定媒体快照与排除条件；模板存在不代表进入统计 |
| `config/{season}_formal_rules.json` | 该季采用的配置和结算口径；各季结构不同，按实际消费者解释 |
| [S23案例规则](../config/S23_review_rules.json) | 有来源、状态及作用域的现场案例／用户确认，不能推广为通用规则 |
| [版型模板目录](../config/board_templates/README.md) | 身份数量、固定事件槽、合法动作、目标及已核 `wake_order` |
| [共有约定](../config/game_rules.json) | 已实现的固定座位、机械狼等约定，使用前核适用范围 |
| [计分配置](../config/scoring_rules.user_reported.v1.json) | 用户报告的计分规则；历史季需单独确认，不声称全部官方验证 |

规则证据查[官源原图](../data/raw/rules/weibo_5228857471013279/README.md)、[研究索引](research/README.md)及当局法官裁定。证据冲突按[字段规范](02_字段证据与交叉复核规范.md#6-冲突与修订闭环)处理，保留未知与局部例外。

## 模板表达什么

固定槽是归档位置。法官叫醒顺序、技能何时可用、实际结算顺序分别核实；只有已确认的 `wake_order` 表示操作顺序，空列表不靠槽位顺序补齐。白天技能按实际时点发生，槽位排在最后不表示最后发动。

底牌、榜样／学习／傀儡／面具等状态分开；傀儡不是第13张身份牌，动态余牌不硬套固定角色数。首夜专属、次夜解锁、资源耗尽、已出局、明确空过、规则禁止与资料未知分别记录。

状态词遵从现有消费者：通用核实记录、S22正式事件和S23专项文件不一定使用同一枚举。例如S22槽位中的 `unavailable` 与S23首夜禁刀的 `forbidden` 不能为了统一文字批量改名。具体字段查[证据矩阵](02_字段证据与交叉复核规范.md#3-逐字段复核矩阵)。

## 维护与验证

1. 新规则先写清赛季／版型／场次、来源、确认日期、已知与未知；不同季真实差异用独立模板，不覆盖旧季。
2. 只有当前需求涉及的规则才调整模板与验证器，核对实际调用方、枚举和导入适配；以一个真实样板验证，再做所需范围。
3. 规则变化时同步受影响的事件、导入和派生结果，运行对应语义回归；文档整理本身不触发重导或重新发布。

现有规则JSON、模板代码、迁移和来源哈希都有消费者，本次只整理文档编号，不改这些文件的名称与内容。历史JSON／收据中的旧文档路径和哈希按原版本解释；查文档迁移用[旧编号对照](archive/README.md#旧编号去向)，不以新路径下文档的哈希替换历史来源哈希。
