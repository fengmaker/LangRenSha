# 字段证据与前后交叉复核规范

核对日期：2026-10-28。自主AI复核或核对他人意见，先按[第六步](02_采集与座位姓名身份核实.md#第六步局部复核与意见核对)限定对局、字段与证据区域，本页只查该字段所需规则。以后接入历史赛季，按[全流程操作手册](15_赛季数据全流程操作手册.md)逐步执行，本页用于判断新增字段的证据和验收条件。已有S22/S23及人名、座位、照片映射已核实，直接复用；不因整理规范重新打开既有定案，也不另填任务单。

## 最小协议：每条信息只做这五件事

1. **定位原件**：BV/CID/P、原文或原图、原媒体时间和SHA；读连续上下文。
2. **分清含义**：底牌与自称、原目标与实际效果、实际死亡与公布时点、理论条件与现场结果分别记录。
3. **核对直接依赖**：只在本次字段需要时核资格、资源、存活和票权，用相关后续结果反查；不逐局重放无关日夜。
4. **定结论级别**：明确观察、因果唯一推断、用户确认或仍未知；多解才问具体问题。
5. **留下依赖**：保存旧值、新值、依据和适用规则；改动后重查受影响的票型、终局、统计和发布版本。

日常局部复核直接只读查看指定证据；下方矩阵按需要查对应字段，无须从头读完。`workflow --stage review --full-season`才运行旧整季结构校验/生成，不能代替事实判断。

## 1. 先分清“说过什么”和“实际发生什么”

同一段资料可能同时包含玩家自称、解说推测、法官指令和实际结果。例如“7号说自己是预言家”可以证明一次身份主张，不能证明7号的底牌。“他如果刀3就赢了”不能证明已经刀3。赛后复盘优先用于身份和夜间实际经过，完整局中时间线用于发言归属、警徽、票型和实际触发时点。

每条结论分别注明：原文明确、画面明确、因果唯一推导、用户确认，或仍未知。它们是复核含义，不要求往正式档案里新增同名枚举。已有 JSON 使用自己的结构；S23 的资料未公开项保留 `not_observed`，不能改成已确认。

多个 ASR 输出相同，只能说明机器稿一致；同一段字幕、SRT、阅读 TXT 是一份证据的不同格式，不能算三份独立佐证。导播摘要也可能复述玩家自称。

## 2. 每个字段都要能回到来源

证据及推断保存在提取、审计和用户反馈文件中；`dossier.json` 等业务档案保存规范化事实，二者通过来源关联、路径和内容哈希绑定。

| 必留内容 | 怎样记录 |
| --- | --- |
| 对象 | 赛季、对局ID、BV、CID、分P；具体到座位、夜次、游戏日或票轮 |
| 来源 | 原音频／原字幕／原图路径及 SHA256；网页来源链接及采集快照 |
| 定位 | 原媒体起止毫秒、截图时点、规则图页码或卡牌位置 |
| 原始内容 | 连续原句、原始画面；保留足够上下文和否定词 |
| 提取与修订 | 机器原稿、阅读整理稿、候选值、修订前后值分别保留 |
| 推导链 | 使用的前提字段、对应证据、适用规则及版本；排除过哪些替代解释 |
| 结论边界 | 哪些已确定，哪些只是可能；是否需要用户判断及具体原因 |
| 依赖 | 这个结论会影响哪些后续日期、存活、票权、胜负、积分或悍跳统计 |

局部 WAV/ASR 的时间是窗口相对时间，写回证据时必须用裁剪收据中的偏移映射到原音轨；不能把片段第20秒当成原视频第20秒。截图保存原尺寸和原字节，标注图、裁剪图另存。

S23 的现有存放方式：`data/extractions/S23/game_reviews/{BVID}/entry.json` 绑定来源；`baseline.*` 是机器起点；`dossier.reviewed.json`、`voting.reviewed.json`、`ai_review.json`、`primary_review.json`、`daily_audit.json` 保存不同层的判断。最终生成时应用审计补丁，不直接抹掉早期判断。新赛季先确定自己的旁证契约，再复用这些概念。

### 3.1 对局、人物与身份

| 字段 | 首选证据 | 可用的补充／交叉证据 | 确认条件与常见误判 |
| --- | --- | --- | --- |
| 官方来源与媒体身份 | 官方账号元数据、BV/CID/P、清单和文件哈希 | 合集索引、同一媒体来源收据 | 核对真实账号和同一分P；标题或文件名相同不代表同一素材 |

| 局次与对局边界 | 法官开局、终局、下一局开局及场上人员 | 标题、同日其他录像、复盘 | 同一媒体可以含多局、同局重复呈现或局部回放；重复呈现不重复计事件或票轮；不能按“每天应有三局”补造 |
| 实际版型与人数 | 法官介绍、现场规则／身份配置图 | 完整底牌组成、官方当日公告 | 标题与轮换顺序只是线索；特殊加赛按实际证明 |
| 统一选手姓名 | 已确认的人名映射、本人介绍、清晰姓名牌 | 同日官方阵容、其他局已核座位 | 复用已有规范姓名；新昵称／别名需有依据。微博名牌识读保留原图、SHA、原帖和确认来源；声纹编号、名单顺序、近似读音不直接当姓名 |
| 姓名—照片 | 官方微博原图名牌及已确认照片映射 | 同帖正文／排班、本人介绍、已有明确别名 | 按原图SHA复用确认依据，不凭人脸或同名确认另一张新图；同季照片、原帖、日期、编号及确认状态可追溯，详见[微博流程](02_采集与座位姓名身份核实.md#确定当天出场嘉宾) |
| 座位—姓名 | 本局姓名牌、法官点名、首局自我介绍 | 同日同阵容且无换座证据的其他局、官方照片 | 微博名单／图片顺序不是座位；跨局复用说明依据，换人换座重核新增资料。既有JY固定7号约定按原作用域使用，新季以现场证据为准 |
| 解说、法官、本局职责 | 节目介绍、片头／画面姓名、明确主持交接 | 官方排班、声音与已确认发言对照 | 人物与职责分开；赛后说话不自动等于解说，同一人可在另一局担任选手 |
| 实际底牌 `role` | 法官连续终局身份复盘、明确真实身份揭晓画面 | 局中翻牌、技能与角色数约束 | 先核画面视角标签；“奇幻视角”的身份伪标不能作底牌证据，姓名与座位名牌仍分字段核对。玩家自称、黄色自称栏、解说推测均不足；角色词常修饰后面的座位，不按字幕断行配对 |
| 未逐名公布的剩余底牌 | 已确定其他座位及当局精确角色配置 | 完整底牌画面、局中明确揭晓 | 只有封闭集合且剩余解唯一才可推导，并标推导；不能把“没读出来”当平民 |
| 胜利阵营 `faction` | 当季规则与实际底牌、明确特殊阵营选择 | 混血榜样事件、法官复盘 | 物理身份、淘汰边、个人胜利阵营分开。混血榜样未知则不硬补阵营 |
| 榜样／学习／傀儡／面具 | 法官逐夜复盘或明确操作／结果揭晓 | 后续查验反馈、技能生效与目标历史 | 分别保存目标、时点、形态／临时状态；学习和面具不改底牌，混血榜样不填进机械学习字段 |
| 查验目标与反馈 | 真实行动者及法官复盘／明确操作结果 | 对应夜、后续公布、规则限定反馈 | 真预言家的实际查验与任何玩家口头报验分开；通灵反馈不必等于目标底牌，反向反馈按当季规则处理 |

S21 的 `BV1qJ9gBZEU8` 已发现“奇幻视角”误当真实底牌的问题：按3013–3021连续终局名单修订8个座位身份，原截图和旧核实记录保留，依赖该名单的日夜行动者重新核对。全122张身份截图的视角标签检查及修订依据见[核查收据](../data/reports/S21_奇幻视角核查.json)。

### 3.2 发言、报名、警徽与票型

| 字段 | 首选证据 | 可用的补充／交叉证据 | 确认条件与常见误判 |
| --- | --- | --- | --- |
| 发言者和起止时间 | 法官点名、镜头／座位高亮与本人连续发言 | 相邻交接、其他人称呼、已核声线 | 抢话、引用、解说插话分别切开；CAM++匿名编号不能直接映射到人 |
| 玩家身份主张 | 本人完整话轮中的明确自称 | 查验／警徽流摘要、后续本人解释、复盘佐证 | 排除“如果我是”、引用他人、转述、反问、单纯宣称获得某技能 |
| 首次上警／警下名单 | 首次报名播报、报名画面 | 首日点名顺序及已核全员名单 | 与退水后的候选池分开。只在确认名单完整时取补集；不能用最终候选反推首次报名 |
| 退水和最终候选 | 明确退水口令、正式投票前候选播报 | 投票合法目标、现场候选标记 | 退水不抹掉此前真实发生的上警或悍跳；不同轮候选池可能不同 |
| 票轮是否举行、属于哪一天 | 真实投票口令、投票段、结果公布 | 画面日号、入夜／天亮、自爆及放逐链 | 标题 Day 是节目日期，不是局内日次；整轮未找到不自动补一轮弃票 |
| 逐人投向、弃票 | 法官逐人播报、清晰票型画面 | 后续复述、公开结果、本人解释 | 有票权且该轮已确认时，按现有用户口径补“默认弃票”，与原文弃票区分；不能用总票数任意分配缺票 |
| 票型图层归属 | 同一游戏日／票轮的清晰截图及图例 | 刚结束的投票播报、切屏前后画面 | S23红底数字为警徽票、绿底数字为放逐票；别季先核图例。后期累计图层不保证显示当前轮 |
| 票权名单 | 投票时的存活、候选、角色状态与适用规则 | 法官点名、此前死亡及技能出局、延期竞选原警下名单 | 投票之后才开枪带走者参与此前票轮；首夜死亡可能竞选后才公布，实际警下票需逐局核对 |
| 警徽票重 | 持徽者在本轮的警徽状态和当季票重规则 | 警徽转移／流失口令、结果票数 | S23预女猎白混的绑票理论票力按确认口径计警长额外半票；S22现有逐人票型归档暂不计算半票。其他场景按本季规则，选票张数与加权票力分开 |
| PK、复投、技能重投 | 实际首轮结果、额外发言和再次投票口令 | 两轮逐人票型、法官说明 | “归票甲乙PK”可能只是双归票；未实际复投不建PK轮。定序王子技能重投单列，不覆盖首轮 |
| 放逐结果／平安日 | 法官最终结果及实际离场 | 加权票数、遗言、后续存活、终局复盘 | 两轮双平票仍保留两轮，结果为无人放逐；不能先按首轮高票判死再重投 |
| 警长归属、移交、撕徽、流徽 | 法官当选及后续处理口令／画面 | 警徽票、下一轮票重、复盘 | 当选与继承警徽不同；延期竞选与同日PK不同。首日中断只延到次日，次日再次自爆流徽是当前已确认口径 |

### 3.3 夜间行动、结算与终局

| 字段 | 首选证据 | 可用的补充／交叉证据 | 确认条件与常见误判 |
| --- | --- | --- | --- |
| 第几夜、对应第几天 | 连续开局／入夜／天亮／死亡口令 | 自爆、放逐、复盘夜次和后续行动 | 开局夜晚单列；第一天白天之后是第一天夜晚，内部第2夜；展示编号与存储编号须有映射 |
| 行动者、原目标 | 法官逐夜复盘、明确操作画面 | 角色存活、技能起用时点、后续反馈 | 操作目标先保存，不因交换、反弹或免疫改写原目标；解说猜刀不当实刀 |
| 狼刀、额外技能刀、接刀 | 法官复盘、真实狼队身份和前序出局 | 机械学习／解锁时点、其他狼是否全灭 | 普通刀与技能刀分开；机械狼或盗宝接刀条件按当季规则核对，不只看“场上只剩一个狼方阵营” |
| 守护、解药、毒药 | 明确复盘和资源使用历史 | 狼刀目标、次日死亡、存活及技能限制 | 同守同救、反弹、交换等须按当局规则结算；不能从平安夜唯一反推是救／守／空刀 |
| 夜间死亡、死因和实际生效者 | 天亮死亡公布、法官结算／复盘 | 原目标、交换映射、梦死、共舞、药量和技能状态 | 原刀口／毒口与实际死者分别保存；有多个可能死因时保留原因未知 |
| 猎人／狼王开枪资格 | 实际出局原因、角色状态与法官允许／禁止 | 实际中毒者、傀儡、梦游连带、终局边界 | 不按毒药原目标判资格；猎人与狼王分开。S23已确认末神猎人出局即终局、无后续开枪窗口，不记主动不开枪；其他季查本季结算 |
| 技能次数、冷却、重复目标 | 适用规则、每轮完整目标历史 | 用药史、学习史、角色死亡时点 | “学习当夜不能用新技能”和“后夜已解锁但未使用”不同；真实违规与DQ保存原尝试及裁定 |
| `pass`／不适用／未知／禁止 | 明确空过口令或适用条件／规则 | 人物已出局、资源耗尽、当夜未解锁 | 未说不等于空过；`unavailable` 等编码遵从当前模板，S23盗宝首夜禁刀为 `forbidden` 且无目标 |
| 白天技能、自爆、DQ、交牌 | 法官口令及实际发生画面／原音 | 前后入夜、存活、终局复盘 | 自爆不自动覆盖已发生票轮；DQ狼刀失效是对应场次裁定，不扩展成所有DQ的规则 |
| 延迟出局 | 法官说明、本人实际发言与离场 | 夜间命中、后续票权、终局 | 中刀时点与公布／离场时点分开；不提前删掉仍实际发生的发言 |
| 独立拍刀 | 明确拍刀声明、法官接受及结算 | 当时存活、终局复盘、明确刀路 | 与普通狼刀、讨论中的假设刀路分开；目标集合不表示刀序，也不等于每个目标均有效死亡 |
| 绑票条件 | 当时个人胜利阵营、可用票权和警徽归属 | 实际票轮、法官终局宣布 | S23预女猎白混已确认：狼混计其胜利阵营，警长半票计持徽者方，狼人方票力大于等于好人方构成绑票；理论达成与实际结束分别记录，其他季不直接继承 |
| 胜方、结束时点 | 现场明确宣布及结算复盘 | 完整存活重放、当季胜利条件、拍刀／交牌裁定 | 淘汰边不等于个人阵营；现场明确边界优先约束展示，理论冲突保留解释，不补造下一天或终局查验 |

### 3.4 悍跳、统计与网站派生结果

| 字段 | 必须核对的证据／条件 | 不能代替它的内容 |
| --- | --- | --- |
| 是否悍跳 | 实际物理狼人底牌、个人狼人胜利阵营、本人公开自称预言家或通灵师；核清话轮和发生日 | 上警、拿徽、被称悍跳狼、引用他人验人、好人诈身份、狼混、只获得某项技能 |
| 首日／延期／后期悍跳 | 从警上、真实PK、警下连续看至真实入夜或自爆；延期到次日和更晚起跳另记 | 次日说法倒填首日；只看节目最后一张摘要图 |
| 悍跳次数 | 同一选手同一局去重，保留每次证据和退水史 | 一局多次自称累加多次；退水后删除曾发生的尝试 |
| 悍跳成功 | 起跳者竞选获得警徽，或首日最终放逐好人；首日放逐条件仅用于首日起跳，延期／后期按已确认发生日核对竞选拿徽 | 首轮暂时高票、夜死、技能出局、次日放逐、事后整局狼人获胜、警徽继承 |
| 悍跳不确定性 | 归属不明不计已识别次数；成功不明排除成功率分母，并留可定位的问题 | 把不确定当失败、把未填写意见当用户同意 |
| 选手胜负／积分 | 个人有效阵营与整局胜方；现行基础分狼胜+1.5、好人胜+1、负-1，规则需逐季核对 | 混血底牌直接等于好人、未知当负场或零分；未取得官方积分就声称官方核定 |
| 出场率与胜率 | 当前选定赛季范围的正式对局／有效出场；胜率只使用有效胜负样本 | 原媒体数当正式局数、缺字幕当缺席、未知结果进负场 |
| 版型好人／狼人胜率 | 各版型对应胜场 ÷ 已确认好人或狼人胜方局数；没有有效样本显示“—” | 删除未知结果列后把未知对局按任一方胜或按0%计算 |
| 上警、站边、警徽票指标 | [统计代码](../website/api/analytics.py)与[积分榜字段说明](../website/积分榜字段说明.txt)规定的分子分母、合法票权和真实信息神 | 把所有玩家发言自动当站边样本；缺少选票自动判投错 |

当前悍跳定义以 [bluffs.py](../website/api/bluffs.py) 为实现入口。2026-10-09第三局10号遗言起跳不计悍跳、该局6号保留，是后续用户明确确认；早期“仍待确认”的处理说明是历史证据，不能覆盖[最新交付记录](../data/reports/S23_悍跳本次交付_20261026.json)。不要把这一场结论自动扩展成尚未确认的所有赛季边界。

## 4. 前向重放：从开局一步步约束后续

仅在本次问题涉及日夜流程或相关资格时，沿受影响部分使用以下顺序；姓名等独立字段不要求重放全局。时间表为：原媒体时间 → 游戏夜／天 → 当时行为 → 实际状态 → 已公布状态 → 证据。实际死亡与何时公布死亡可能不同。

1. 冻结当局版型、12座姓名／底牌候选、特殊状态及未知项，先列规则适用范围。
2. 从开局夜晚重放行动：行动者是否有资格、技能何时解锁、资源是否剩余、原目标及实际效果。
3. 结合天亮播报确认死亡；只记录已证明的死因。首夜死者竞选期间的实际发言和投票单独核查。
4. 到每个真实投票时点重建票权、候选、警徽；逐人比对选票与加权结果。
5. 投票结算之后再加入枪带人、白天技能、自爆、DQ及警徽变化，不能提前扣人。
6. 重放入夜后的行动、资源消耗和目标限制；检测角色重复使用、已出局仍行动等矛盾。
7. 每个可能终局点检查物理淘汰边和现场裁定。结束后的节目复盘不建成下一天游戏流程。

S22 已有 `game_flow.py`、`voting_rules.py`、`voting_crosscheck.py` 等辅助实现；对S23／新赛季，应先核查它们对新版型的支持，不能把“运行无报错”当成每种技能都已覆盖。

## 5. 后向核对：用明确结果检验前面哪一步有误

只回看与本次矛盾有关的前提，能解释并确定本次结论即可停止。

| 后面已经明确的事实 | 回看哪些前提 | 可以得到什么，不能得到什么 |
| --- | --- | --- |
| 某人在下一天实际发言或投票 | 前夜死者、延迟出局、日次、说话者归属 | 排查错误日序或误归死亡；不能仅凭出现声音认定未死 |
| 后续出现第二次用毒／重复学习 | 第一次是否误听、是普通还是机械技能、资源和换目标 | 暴露主体／夜次错误；不能直接删掉早先记录让规则“变对” |
| 明确最终放逐与票数不符 | 警长票重、弃票、PK轮、漏票、投票日期 | 有唯一解释才接受修正；只有总票数不能任意分配逐人投向 |
| 法官复盘公布完整底牌 | 首日话轮、查验真伪、狼队技能资格 | 识别真实身份与悍跳归属；不能把终局已知身份写成玩家首日已知信息 |
| 明确平安夜或双死 | 守／救／毒／梦／交换／舞池／DQ及其资格 | 按适用规则枚举并排除解释；多个原因仍可能时保留未知 |
| 宣布胜负／拍刀结束 | 终局前存活、有效刀口、淘汰边、裁定原文 | 定位终局边界；规则不全时不能靠理论名单推翻现场事实 |

推导接受条件：前提都有来源、用到的规则适用于本季本版型、不存在尚未排除的合理替代解释，并保存推导过程。缺少直接播报不必然产生人工待办；因果链唯一时可形成“推导结论”。仍有多解时，把问题缩到具体字段与具体两个解释，再请用户裁定。

## 6. 冲突与修订闭环

1. 先排除错源：BV/CID、分P、日次、字幕版本、时间偏移、上一局残留图层。
2. 连读对应原句的必要上下文；数字、名字、否定词或话轮仍有歧义时才回听原音，必要时用Nano片段复识别。
3. 画面、话轮或图层归属出现冲突时，补看同一时点相邻画面及必要图例；平台摘要不能单独胜出。
4. 分开“事实冲突”与“规则缺口”。规则查本季登记册、官源原图、当局法官裁定及适用的用户确认；不同赛季不得直接继承。
5. 若仍矛盾，保留双方原证据和具体未决字段。规则例外保存为当局裁定，不擅自扩展为通用规则。
6. 已获本次修订授权时，更新对应旁证／补丁，记旧值、新值和理由；只重查实际受影响的存活、票权、终局或统计。
7. 候选快照改变后，旧反馈先校验快照与哈希；不匹配不能直接覆盖。重新入库／发布后核对网站实际读到的新版本。

## 7. 复核完成的可检查标准

以下标准适用于本轮指定范围及已触发的直接依赖；局部完成不代表其他对局或字段本轮已核。所提问题有结论或明确缺口即可收尾。

- 本轮目标有范围、来源，以及该结论实际使用的转写／规则版本和证据位置。
- 本轮核对字段有明确来源或完整推导链；未知／未发动／不适用／禁止没有互相替换。
- 所有实际投票轮均保留，出局前后、自爆延期和本季已确认的警徽票重一致；未发生的轮次没有补造。
- 已知夜间行动、资源、特殊结算和终局前后相容；仍未知的特殊规则明确列出。

- 正式档案、数据库回执、悍跳发布资产和网站活动版本可以相互对应。

结构检查通过、没有人工待办、整批获得发布授权，以及每个字段都经人工确认，是不同的完成状态，应分别报告。
