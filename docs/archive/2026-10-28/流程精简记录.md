# 采集与核实流程精简记录

归档日期：2026-10-28。以下记录此前流程精简的决定与保留理由；日常执行见[赛季数据全流程](../../01_赛季数据全流程.md)。


| 机制 | 决定与依据 |
| --- | --- |
| 采集时连接数据库、自动登记、再跑媒体解码校验 | 移出纯采集路径；原始登记仍由 `collect_official_audio.py` 显式执行，已有数据、事务及其测试保留 |
| 自动字幕版本择优、全季音频/DB一致性审计 | 从collect调度移除；历史快照确有消费者，原工具保留为后续显式操作 |
| 线程池、双层节流、停止事件、自动重试、固定8 GiB门槛 | 删除；本步顺序请求，复用采集器已有请求间隔与单文件上限；错误明确停止 |
| 重复的待办列表、运行计数副本、内部返回值重复校验 | 删除；进度只记录条目结果、必要汇总和运行状态；CID仍需对冻结来源核对 |
| 无调用方的字幕语言可配置筛选 | 删除；当前需求固定为中文轨 |
| 微博归档的关键词命中字段和重复统计 | 删除；本步全量采集，普通有限采样器的关键词功能保留 |
| 认证模块缺失时退回匿名、旧帖文件缺失时猜路径 | 删除；项目依赖明确，缺失应报错；旧帖猜路径也不能正确完成原清单路径迁移 |
| 音频、微博图片SHA256及原件关联 | 保留；已用于损坏检测、续采复用、数据库及姓名照片证据引用，不新增发布指纹或全仓扫描 |
| Cookie域隔离、官方作者/BV/CID/P、路径与下载长度检查 | 保留；它们分别约束凭据去向、资料来源、文件写入位置和未完成下载 |
| 中文轨失败与无轨的区分、字幕段落格式校验 | 保留；防止失败触发音频下载，格式约束在入口维护，后续导出复用同一函数 |
| 微博游标、原帖ID、长文/图片状态、三页日期终止条件 | 保留；分别支持续采、去重、补齐多图与避免置顶旧帖造成提前结束 |
| 已有API字段读取、seed跨目录硬链接失败后复制、历史版本哈希 | 保留既有输入/文件系统契约；本轮没有证明删除这些分支不会破坏现有读取、跨盘复用及历史证据 |

| 第二步机制 | 处理与理由 |
| --- | --- |
| 默认先跑完整ASR、声纹或多个模型 | 从日常必跑流程去掉；复用已有文字，缺稿才转写，现有 `--no-speakers` 直接可用，第二份机器稿只在疑点时选用 |
| transcribe调度后的自动DB登记 | 删除该串联；转写阶段只生成文字，原登记脚本保留为明确写入入口 |
| `prepare_s21_review_candidates.py` 的范围外候选 | 不列入第二步默认命令；三类身份事实不依赖先完成日夜、投票或胜负推断 |
| 照片/截图/文字来源SHA、ASR配置与VAD计划 | 保留；用于同图复用、证据引用和防止不同音轨/热词/分段结果混用 |
| `raw/chunk_*.json` 检查点与原时间偏移 | 保留；支持长音频续跑及完整覆盖，当前没有额外的chunk内容哈希，不把区间校验称为“检查点哈希” |
| 旧截图定位回退、无明确复盘开场时的候选定位 | 保留真实旧证据消费者；定位候选须核图，旧请求时间明确与实际PTS区分，不由fallback直接确认身份 |
| 重复出现的哈希与导出校验 | 本轮未发现可证明安全删除的证据边界；它们分别覆盖原件、人工编辑后结果和长任务期间来源变化，不新增全量复验 |
