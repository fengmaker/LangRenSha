规则来源标记：`user_reported`。适用历史赛季：逐季核实。以下规则未逐季找到并核对官方原帖/规则页，故均不得标记为 `official_verified`。本文是采集与待核验规范，不是官方赛制公告。

## 1. 录入原则与赛事分类

每条对局记录必须分别记录：赛季、赛事阶段、周/期/日、局序、是否加赛、是否计入所讨论的积分榜、是否纳入统计。不得由“第 4 局”自动推断其加赛性质或计分资格。

赛事阶段至少使用：

- `showmatch`：表演赛。
- `regular`：正赛。
- `finals_week`：决赛周。
- `unknown`：来源不能判定。

`is_extra_game` 单独记录 `true/false/unknown`；`scoring_eligible` 与 `included_in_analysis` 也单独记录。对局存在、结果可归档，与该局是否计分、是否纳入某个积分统计是不同问题。

### 用户报告的赛制规则（逐季待核）

| 规则 | 采集解释 | 状态 |
|---|---|---|
| 每季第一周为表演赛 | 作为阶段候选，须按该季官方赛程确认 | `user_reported` |
| 19:00 开始 | 暂按北京时间记为用户报告开赛时间；例外和判定依据未知 | `user_reported` |
| 前三局在 22:30 前结束，可加赛第 4 局 | 这是加赛触发条件，不是“必有第 4 局”；是否实际开赛、是否属于加赛，以当晚录像/官方赛程确认 | `user_reported` |
| 正赛第 4 局计分 | 仅在阶段被确认是正赛且规则适用于该季时标为可计分 | `user_reported` |
| 表演赛不计赛季正式积分 | 表演赛结果仍可记录、分析；正式积分资格为否 | `user_reported` |
| 决赛周第 4 局加赛不计分 | 该局若实际存在，仍照常归档局结果；只将该局正式积分资格设为否 | `user_reported` |
| 决赛周积分清零后重算 | 决赛周开始前积分不带入该周冠军计算；计分局总分最高者为季冠军 | `user_reported` |
| 狼人阵营胜 +1.5；好人阵营胜 +1；任一方负 -1 | 暂按每位座位选手的最终计分身份/所属方胜负记基础分；混血、第三方及特殊身份结算不能自动套用 | `user_reported` |

“22:30 前结束”所指的精确事件/时间戳（如第三局结算、直播结束或游戏结束）、遇到超时或暂停的处理、19:00 规则例外均未知。不得自行制定边界规则。

## 2. 逐局采集字段

所有时间记录北京时间并保留原始来源时间。不能确认时填 `null` 或 `unknown`，不以猜测补齐。

### P0：必采事实

**对局层**

- `match_id`：内部稳定 ID；不要用标题代替。
- `season_id`、`event_date`、`phase`、`week_or_stage`、`day`。
- `game_number`、`is_extra_game`、`scoring_eligible`、`included_in_analysis`。
- `start_time_reported`、`end_or_trigger_time`：注明来源与时间定义；未知则 null。
- `result_summary`：只记录来源明确揭晓的结果。
- `sources[]`：URL/接口、来源类型、获取时间、媒体时间戳区间或 API 字段定位、可访问状态。

**每个座位选手**

- `seat_number`、`player_id`（仅有稳定 ID 时）、`nickname_as_broadcast`（当场原样昵称）。
- `opening_role`、`opening_faction`。
- `settlement_faction_or_scoring_identity`：结算/计分身份；证据不足时填 `unknown`。
- `personal_result`：`win/loss/draw/no_result/unknown`；已知平局仍记录 `draw`，只将尚未确认的平局积分保留为 null，不把已知结果改成未知。
- `base_points`、`adjustments`、`official_points` 三个字段分别存储，不能互相覆盖。
- 每条事实的 `sources[]`，并尽可能记录 `media_timestamp_start/end`；API 元数据用字段名/响应定位，媒体时间码可为 null。

计算出的分值放入 `base_points`；有明确依据的奖励/扣罚放入 `adjustments`；官方公布积分单/排名里的实际分值才填 `official_points`。只有规则及各项都确认时才计算 `base_points + adjustments`。不把计算值冒充官方公布值。

### P1：可选的局内事件

有来源和时间码时可采：投票次序与票型、放逐/出局、夜间行动与目标、警徽流/移交、公开技能发动、关键发言或状态变化。每个事件都记录局内时间和证据来源；不明确的事件只进待核候选层。

### P2：主观分析标签

例如发言风格、策略类型、可信度、情绪/节奏标签。标注为分析者解释，须有定义、标注者和理由；不可回填为 P0 事实，也不可用于自动改变官方积分。

## 3. 四层证据分开保存

1. **音频原件层**：保留原始文件不覆盖；记录 BVID/CID、获取时间、文件哈希、编码/时长、来源 URL 和访问条件。音频只能证明可听到的内容，不能替代画面中的角色卡或最终结算图。
2. **ASR 逐段稿层**：逐段保留原文、开始/结束时间、模型/参数、可选 speaker ID 和置信信息。所有转写和说话人分段均为机器候选，不直接成为已核验事实。
3. **结构化候选层**：将 ASR/画面/OCR 候选映射到 P0/P1 字段；保留原始候选、提出方式和待核标记，不覆盖源记录。
4. **人工核验事实层**：逐字段由人工对照来源确认；记录核验人、核验日期、URL、媒体时间码或 API 字段。无法判定继续为 unknown/null。只有此层事实可进入已核验统计。

自我介绍只能作为“当晚嘉宾候选”，不能据此推断每一局都有同样 12 名选手或确定各局座位。局中自称角色可能是策略性谎称；赛后复盘也可能省略或记错。角色身份优先依据终局揭晓、法官明确的终局身份播报、角色卡/身份展示或可核验官方结算材料，并保存对应时间码。音频足以明确终局事实时可以经复核采用；音频不完整、有人名歧义或来源冲突时，只补取关键画面核验，不必默认下载整段视频。不得从局中自称或含糊的复盘推定身份。

## 4. 未知项与复核清单

以下内容在本轮仅有用户报告，必须逐赛季查官方资料或完整可核验录像：

- 平局、流局及个人结果如何计分。
- 混血/第三方阵营、身份转换、特殊胜负条件如何结算。
- 奖励、扣罚、MVP、特殊加分及其和基础分关系。
- 跨季规则是否改变，用户报告的规则是否适用于 S20、S21、S22、S23 等各季。
- 每季第一周表演赛、19:00 开始的例外。
- “22:30 前结束”的判定时点、时区及暂停/延迟处理。
- 决赛周若并列最高分如何决定季冠军。
- 具体对局阶段、是否加赛、是否实际计分；不能仅由标题或局序推断。

复核时优先查该季官方账号原帖/原始发布规则、赛事公告、官方积分榜和对局原始投稿。记录原链接、发布/赛事日期、访问日期及原文对应字段；粉丝搬运、搜索摘要、聚合转载只作发现线索，不足以单独标记官方已核验。

## 7. 交付前检查

- [ ] 每条对局和每个选手记录能回到来源 URL；事实尽量有媒体时间码。
- [ ] 阶段、局序、加赛标记、计分资格、统计资格分别填写。
- [ ] 不把当晚嘉宾名单扩展成每局参赛名单；不把自称身份当作真实身份。
- [ ] 原始音频、ASR、结构化候选、人工核验记录分别保存且可追溯。
- [ ] 分值的基础分、调整项、官方分独立；规则未核实则 null/unknown。
- [ ] 每季规则状态如实记录为 `user_reported`、`source_acquired`、`needs_review` 或经证据确认后的状态；无官方原始证据时绝不写 `official_verified`。

## 8. 音频到数据的执行顺序

先查可见字幕；没有合适字幕则获取独立音轨；生成带时间戳的 ASR；再按比赛切分，提取“座次名单、真实身份候选、结算候选、事件候选”；最后核验并入库。长录音分段处理但保留全局时间偏移，不能丢掉片段与原录像的对应关系。

每局描述作为派生摘要保存，建议包含“赛事与板子、已核验参赛者、按日夜顺序的关键事件、明确结算、尚不确定内容、对应证据”。摘要可由转写生成，但不能把原话中的猜测改写成已发生事实，也不能替代结构化座次与结果表。
