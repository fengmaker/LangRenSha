# 微博历史帖子采集

> 历史参考：本文件保留此前方案与试验过程。当前执行范围以 [项目入口](../../../README.md) 和 [三步路线](../../01_项目路线.md) 为准；当前只推进第一步原始媒体采集。旧文中的“下一步”不作为当前任务。

入口：`scripts/collect_weibo.py`。依赖 `requests` 和 Python 标准库，不使用浏览器自动化。默认 `--auth none`，只读取无需登录即可访问的页面；仅明确指定 `--auth cookies --cookies-file PATH` 时才交给项目的 `auth_support.configure_session(..., platform="weibo")` 读取 Cookie。认证值不会打印或写入采集结果。没有 `auth_support.py` 时，无认证模式仍可运行，Cookie 模式会明确报错。

所有结果写入 `data/raw/weibo/<UTC时间>_<模式>_<对象>/`：每个保留帖子一个 `posts/<post_id>.json` 原始帖子对象；`manifest.json` 记录归一化正文、来源 UID、日期、关键词命中、每页计数、终止原因和覆盖限制。图片默认只记录去掉查询参数的来源地址并标为 `not_downloaded`；带 `--download-images` 才通过 HTTPS 下载 Sina 图片域的图片，并记录相对路径、大小、MIME 类型和 SHA-256。图片使用流式读取，先检查 `Content-Length`，再逐块限制实际字节数；超出 12 MiB 即关闭响应并丢弃临时文件。每帖最多下载 12 张。不会下载视频或评论。

## 命令

采集一个明确帖子。`--post` 接受帖子 ID 或微博 URL：

```powershell
python scripts/collect_weibo.py --post https://www.weibo.com/7525583841/Q6cG6kgmH
```

按作者日期范围取有限页，关键词以逗号分隔，任意一个词命中即记为候选：

```powershell
python scripts/collect_weibo.py --uid 7525583841 --since 2025-08-01 --until 2025-09-30 --keyword "阵容,积分,规则" --max-pages 5
```

作者窗口日期首尾均包含；默认最多 3 页，`--max-pages` 可设为 1–50。分页请求使用微博移动端 `getIndex` 的 `since_id` 游标。代码不会因某页出现早于起始日期的帖子而提前停止，因为置顶和乱序帖子可能混在列表中。只有接口明确给出末页、返回空页、游标缺失/重复或连续重复页时才停止；未知分页状态会继续到页数上限。关键词是帖子正文的简单候选筛选，命中不等于内容已经被核实为京城大师赛事实。

需要使用用户自己提供的登录 Cookie 时，必须显式给路径：

```powershell
python scripts/collect_weibo.py --auth cookies --cookies-file "D:\private\weibo-cookies.txt" --post Q6cG6kgmH
```

`--auth none` 是默认值；在该模式传 `--cookies-file` 会报参数错误，避免误读文件。Cookie 文件格式由项目共用的 `auth_support.py` 规定。脚本不会登录、解验证码、尝试绕过风控或自动刷新 Cookie。

添加可选图片下载：

```powershell
python scripts/collect_weibo.py --post Q6cG6kgmH --download-images
```

## 结果状态和历史边界

精确帖子读取成功时状态为 `collected`。作者分页结果始终为 `partial`，即使接口给出末页标记，也只能说明本次可见接口页已结束，不能证明找齐作者历史。`login_required` 表示返回登录要求；`blocked` 表示 HTTP 限制、验证码/风控或接口拒绝；若已经取得若干页后遇到限制，则记为 `partial` 并把限制作为警告。空列表只记作 `empty_page_without_end_marker`，不会报告“无历史”。请求异常只显示异常类型或 HTTP 状态，不输出完整请求 URL、查询参数或响应正文。

微博公开页、移动端列表页和历史接口可能只暴露部分内容。帖子删除、可见性设置、未登录不可见内容、搜索或列表索引缺失、接口改版、分页上限和置顶/乱序都会造成遗漏。范围结果只表示“本次可见页中的样本”。需要更稳定的正式读取接口时，微博官方开放平台当前说明提供 `statuses/user_timeline/other` 等接口，但使用前要完成开发者认证、OAuth 授权及服务开通；本脚本没有伪装成该正式 API，也不替用户申请权限。

本次对执行入口做了 3 次无 Cookie、无跳转跟随的最小 HTTP 探测：已知帖子移动端详情返回 HTTP 302；微博桌面帖子页也返回 HTTP 302 且页面提示登录/验证；作者移动端时间线第一页返回 HTTP 432、无 JSON 正文。因而当前环境下不能声称这些命令在无认证模式可实际取回帖子/历史。脚本仍提供精确 ID 与有限游标分页入口，供已正常公开可读的网络环境或用户显式提供自身 Cookie 后使用；如果再次遇到上述边界，会把它记为 `login_required` 或 `blocked`，停止请求并保存 manifest，不把空结果解释成无历史。

随后主代理直接执行 `collect_weibo.py --post Q6cG6kgmH --auth none`，实际联网返回 HTTP 302，状态 `blocked/http_error`、0 帖。诊断清单见 `data/raw/weibo/20261020T045820Z_post_Q6cG6kgmH/manifest.json`，数据库导入结果为 0 条。此前受本机网络沙箱影响的一次请求记录为 `network_error`，不能把它算作微博接口响应。
