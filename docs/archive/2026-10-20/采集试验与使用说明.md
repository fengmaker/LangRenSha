## 音频试验

- 元数据标记时长：3936 秒，约 65 分 36 秒。
- 下载文件：[audio.m4a](../../../data/raw/bilibili/BV1tj8p6REqy/p01/audio.m4a)。
- 大小：52,034,797 字节，约 49.6 MiB。
- SHA-256：`a262189fed43ce506c3149150ae50bde55c8efcc3a2250a586125b7a2e70b5dd`。
- 媒体容器实测只有 AAC 音轨，没有画面轨；解码时长约 3935.53 秒。
- 直接保存平台提供的独立音轨，未下载完整视频再抽音频；本例不需要额外安装系统 FFmpeg。

在 64—128 kbit/s 的假设下，1 小时压缩音频约为 28.8—57.6 MB（十进制，不含少量容器开销）。这是按码率计算的估计，实际下载以平台可用音轨和文件大小为准。将完整视频下载后再删除画面不能节省最初的网络下载量。

## 转写试验与限制

本机为 CPU 推理，使用多语言 Whisper base 的 faster-whisper 实现、INT8 计算。音频没有上传到语音识别服务。

- 初步样本：曾生成开头 2 分钟与结尾 3 分钟的 `BV1tj8p6REqy.sample.asr.json`。该次使用术语提示，开头存在疑似复述提示词的问题，不能直接采用；此初版 JSON/SRT 已在目录清理时删除，修订样本继续保留。
- 修订样本：去掉提示词，选择开头 3 分钟和 60:00—65:35，输出 `data/transcripts/BV1tj8p6REqy.sample.v2.asr.json` 和同名 SRT。
- 样本显示片头含音乐/宣传，尾部包含局内讨论、法官复盘、活动介绍和解说，并非干净的“嘉宾介绍—整局—身份表”。
- 人名、角色名、数字和术语存在明显转写错误，当前只验证了技术流程，不宣称达到可自动入库的准确率。
- 当前模型未做说话人分离，不能把音色或 speaker ID 自动当作玩家姓名，也不能把解说的声音当成座位玩家。
- 后续已完成全文转写，共 2,107 段，见 `data/transcripts/BV1tj8p6REqy.full.asr.json` 和同名 SRT；尚未完成人工身份/结算核验，任何结果、角色和积分仍未进入正式发布版本。

修订样本共输出 169 段机器转写。约 61:38—61:59 能定位到法官终局身份复盘，已据此整理[12 座身份候选 JSON](../../../data/candidates/BV1tj8p6REqy.game.candidate.json)，保留对应 ASR 段号和时间码，玩家姓名与积分仍为空。该文件是待复核候选，不是已核验 L1。样本中还出现“10 号投给 22 号”的转写，超出 12 座位范围，说明必须增加座位合法性检查，不能自动改成某个看起来合理的座位。

下一步按用户最新决定，先人工复核这条视频的“嘉宾及座次介绍、终局身份揭晓、法官复盘”，记录昵称/座位、角色/阵营、胜负和时间定位问题与复核用时。若关键字段能高效补齐，继续使用现有 base；有明确瓶颈才比较其他模型。文字整体通顺不能代替关键字段准确。

流程建议：`可见字幕检查 → 独立音轨 → 带时间戳 ASR → 片头/局内/揭晓/复盘分段 → 结构化候选和摘要 → 人工核验 → 入库`。音频不足的字段补取关键画面，保留证据时间点。

## 现有工具与新增入口

原工具位置为 `D:\person idea\MediaCrawler`。其 B 站实现已包含独立 DASH 音轨选择，但默认下载路径仍把视频轨与音轨合并。本次在当前项目中建立小型独立入口，没有改动原工具的配置或浏览器会话。

- [collect_bilibili_audio.py](../../../scripts/collect_bilibili_audio.py)：按 BVID 获取元数据及可见字幕；显式指定 `--audio` 时只选独立 `audio/mp4` 音轨，无音轨则停止，不回退下载视频。
- [export_collection_index.py](../../../scripts/export_collection_index.py)：从已保存响应导出合集候选索引，不额外请求网络。
- [transcribe_audio.py](../../../scripts/transcribe_audio.py)：本地转写指定时间范围，输出未核验分段 JSON 和 SRT，保留原音频时间偏移。

`BV + 分P/CID` 是媒体定位；比赛 ID 应另外建立。不要把一个包含多局的分 P 自动当成一局，也不要把多个录像版本自动当成多局。

## 复用命令

在 `D:\langrensha` 执行。采集需要 `requests`，依赖见 `requirements-collection.txt`。

```powershell
# 默认只采索引和本次可见字幕
python scripts/collect_bilibili_audio.py BV1tj8p6REqy BV1z6tG6rEfw

# 显式只下载一条独立音轨；已有文件且哈希相同则复用
python scripts/collect_bilibili_audio.py --audio BV1tj8p6REqy

# 从接口响应导出合集索引
python scripts/export_collection_index.py data/raw/bilibili/BV1tj8p6REqy/p01/metadata.raw.json data/indexes/S22_官方合集_候选索引.csv

# 已有独立转写环境及已下载模型：先做局部样本
.\.venv-asr\Scripts\python.exe scripts/transcribe_audio.py data/raw/bilibili/BV1tj8p6REqy/p01/audio.m4a --model .models/base-local --offline --clips 0:180,3600:3935 --out data/transcripts/BV1tj8p6REqy.sample.v2.asr.json

# 确认样本质量后，才执行整局转写
.\.venv-asr\Scripts\python.exe scripts/transcribe_audio.py data/raw/bilibili/BV1tj8p6REqy/p01/audio.m4a --model .models/base-local --offline --clips full --out data/transcripts/BV1tj8p6REqy.full.asr.json
```

若重建环境，使用 `python -m venv .venv-asr`，再由该环境的 Python 安装 `requirements-asr.txt`。已验证 `faster-whisper 1.2.1 + PyAV 16.1.0` 可解码该音频；本次 PyAV 19 与其 `metadata_errors` 调用不兼容，故固定了版本。模型目录与下载哈希保存在 `.models/base-local`；普通 `--model base` 可自动获取模型，但本次自动下载较慢，实际改用同一公开仓库的普通 HTTPS 文件下载。模型来源见[官方模型仓库](https://huggingface.co/Systran/faster-whisper-base)。

音频采集默认上限为 200 MiB、单轨码率 128000 bit/s，串行访问接口，出错即停止批次。接口返回访问限制时不会自动绕过登录、验证码或其他访问要求。大规模批次应在样板核验后再安排。
