## 分享给其他人一起复核

每人填写姓名或代号，可按日期、版型、局次或BV号分工，逐局、逐项及逐座位/事件提出意见。点击“导出我的意见”生成JSON文件后交回；“导入意见”可比较其他人的意见，也能恢复之前的复核进度。浏览器暂存与HTML文件分别保存；分享意见必须携带导出的JSON文件。多人各自复核，不会自动同步。

离线文件是资料快照，不连接数据库；意见带有快照编号和每局档案哈希，供汇总时校对来源。原视频按需通过外链查看，音视频没有内嵌。本机工作台仍用于正式业务更正和入库。重新生成离线资料：

```powershell
.\.venv\Scripts\python.exe scripts/export_s22_offline_review.py
```

文件完整性结果见[离线分享版验收](../../../data/reports/S22_离线分享版验收.json)。

## 从这里开始

打开 [S22 可编辑审校工作台](http://127.0.0.1:8766/)，选择“有待核对项”，即可逐项看原句、时间和候选值，定位完整转写，修改座位、身份、胜负或逐轮事件，再点“保存更正并入库”。疑点备注和勾选状态会同时保存；“保存并下一局”可连续处理。所有疑点均已勾选后，才可点击“标记本局复核完成”。

若电脑重启或服务未运行，在项目根目录启动：

```powershell
.\.venv\Scripts\python.exe scripts\s22_review_server.py
```

服务只监听本机。原有 [批量复核页](../../../data/games/S22/批量复核.html) 和各局 `复核.html` 仍可离线阅读，其中也有可编辑入口。[待复核疑点 CSV](../../../data/games/S22/待复核疑点.csv) 汇总字段、原因、原句、时间、核对结论和逐局链接；它是导出清单，实际更正请在工作台保存。

[按日座位总表](../../../data/extractions/S22/按日座位表/按日座位表.html)集中展示当前47个比赛日的12座姓名，148局共1776个姓名均已齐全，画面待核项为0。工作台保留来源截图、画面 ID 和规范姓名，点击姓名可查看来源截图。同日复用只复用姓名与座号，游戏身份和逐轮事件仍按各局资料分别记录。原始 OCR、按日座位表、同日展开标注分别保存在 `data/extractions/S22/frame_seats/`、`按日座位表/`、`day_frame_seats/`；画面导入续接位置见 `data/reports/S22_画面座位补全进度.json`。

文字补充进度单独记录在 [逐句核对进度](../../../data/reports/S22_转写逐句复核进度.json)，其中 `next_text_bvid` 指向下一局尚未处理的文字，`pending` 为剩余数量。查看进度或将新增的逐句核对结果写回：

```powershell
.\.venv\Scripts\python.exe scripts\s22_text_review.py status
.\.venv\Scripts\python.exe scripts\s22_text_review.py apply
```

逐句核对结果位于 `data/extractions/S22/逐句核对_*.json`，绑定原复盘文字 SHA256；原文变化时拒绝沿用旧结果。原入库档案保存在 `data/archive/S22_text_review/`，你的更正前档案保存在 `data/archive/S22_user_review/`。无改动的结果不会重复入库；新候选与已有已知值冲突时留双方候选，供你确认。文本没有说到的槽位保持未知，不补成空过、平民或推测票型。

下面的命令用于首轮批处理状态和既有维护方式。

在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe scripts\batch_s22.py status
```

`status` 同时显示磁盘进度和当前数据库统计。继续处理时看两个字段：

- `next_bvid`：下一条尚未完成的处理项，包括失败后待重试项。

## 处理、续跑和范围执行

全量运行：

```powershell
.\.venv\Scripts\python.exe scripts\batch_s22.py run
```

同一命令可以续跑，并按 `config/S22_game_scope.json` 中的正式范围过滤。脚本会跳过输入未变、已有数据库收据且数据库记录仍存在的已入库项；已保护的示例或人工档案也会跳过。失败项会保留失败原因并在下次运行时重试。每局单独使用数据库事务，进度在处理过程中原子保存；中断后重新运行即可从进度继续。

只处理某局，或限制本次成功处理的条目数：

```powershell
.\.venv\Scripts\python.exe scripts\batch_s22.py run --bvid BV1xxxxxxxxx
.\.venv\Scripts\python.exe scripts\batch_s22.py run --limit 5
```

可组合 `--bvid` 和 `--limit`。失败项会记录并等待重试，不计入成功处理数量上限。需要先生成档案但暂不写数据库时使用 `--prepare-only`，例如：

```powershell
.\.venv\Scripts\python.exe scripts\batch_s22.py run --bvid BV1xxxxxxxxx --prepare-only
```

正式批处理会先在 `data/backups/` 创建数据库备份；备份相对路径记录在进度文件的 `backup` 字段。备份失败时脚本停止写入。只运行 `--prepare-only` 不执行数据库迁移或入库。

## 每局复核

从批量页面打开该局目录，先看 `复核.html` 或 `复核.md` 的问题清单，再对照原文和表格。常用材料如下：

| 文件 | 用途 |
|---|---|
| `dossier.json` | 当前对局业务记录；工作台保存时更新，也可按下文手工维护。 |
| `复盘原文.txt`、`复盘定位.json` | 自动定位到的复盘文字和定位状态。原文是机器定位结果，数字、否定词和归属仍需核对。 |
| `定位上下文.txt` | 没有定位到集中复盘、但有候选片段时提供回听上下文；它不是法官复盘，也未作为游戏事实。 |
| `座位身份.csv`、`游戏事件.csv` | 方便逐项检查座位、身份、动作、行动者、目标和结果。 |
| `复核记录.json` | 独立保存文字核对摘要、具体疑点、原句时间、已填写的核对结论和原文定位。 |
| `database_receipt.json` | 数据库入库收据；已入库档案通常会有此文件。 |

复核身份与事件时遵守这几条：

- 游戏身份、阵营和行动分别依据各局转写；座位姓名依据同日视频姓名牌，或明确的玩家自我介绍。同日座位表只复用姓名和座号。JY 也需有本日姓名牌或自我介绍依据，无法唯一确认的姓名留空。
- 有本地全文稿的条目优先使用；其余使用现存平台中文字幕。遇到没有集中复盘的对局，查看 `复盘定位.json` 和 `定位上下文.txt`，不要把候选上下文当成复盘事实。
- `unknown` 表示资料未确认。它不等于“空过”“弃票”或“平民”；票型没有依据时不补造。只有原文明确支持时，才改成已发生、空过、不可用、弃票或具体身份。
- 按用户2026-10-24的授权，可结合完整名单、明确余牌、版型数量与结局反推；只有约束唯一且与逐轮行动一致时才写回，并在独立复核记录解释推断。不能唯一确定的动态身份、胜负条件或票型保留未知。

少数稀有版型另有 AI 对明确复盘逐句整理的特殊动作补录，保存在 `data/extractions/S22/复盘特殊动作补录.json`，仍属于待复核机器整理。补录绑定对应 `复盘原文.txt` 的哈希，只能加入解析器已有轮次；原文变化或轮次不匹配时停止采用，并在问题清单提示，不沿用旧动作。

## 修正、重新入库和标记已复核

人工核对后，在 `dossier.json` 中修正有证据支持的业务事实，再重新导入该局：

```powershell
.\.venv\Scripts\python.exe scripts\batch_s22.py import-edits --bvid BV1xxxxxxxxx
```

`import-edits` 会重新校验并写入该局、更新 `database_receipt.json`、`复核记录.json`、复核页和进度。重新入库后仍是待复核状态；导入本身不会替人确认。不要在 `dossier.json` 中加入审核或证据字段，复核状态保存在独立进度和复核记录中。

确认已经逐项核对后，再标记人工复核完成，并写简短说明：

```powershell
.\.venv\Scripts\python.exe scripts\batch_s22.py mark-reviewed --bvid BV1xxxxxxxxx --note "已对照复盘原文和事件表核对"
```

如果档案在重新入库后又被修改，先重新运行 `import-edits`，再标记已复核。尚未检查的对局不要执行该命令。

## 进度与续接位置

批量状态文件和逐步日志分别是 [批量进度 JSON](../../../data/reports/S22_对局批处理进度.json) 与 [批量日志 JSONL](../../../data/reports/S22_对局批处理日志.jsonl)。进度文件是续跑依据，日志用于追查每局处理和失败过程；不要手工把失败改成完成，也不要用复核状态替代数据库业务事实。

下一次打开项目时，先运行 `status`：用 `next_bvid` 找待处理或待重试项，用 `next_review_bvid` 找待复核项。失败、未知和待复核都保留为明确状态，不会伪装成已完成。各版型角色和事件口径见 [S22 版型规则与夜间顺序](版型规则与夜间顺序.md)。

需要重新检查档案与数据库是否一致时，运行只读验收：

```powershell
.\.venv\Scripts\python.exe scripts\audit_s22_batch.py
```

结果保存在 `data/reports/S22_对局批处理验收.json`。验收逐局比较座位、身份、机械学习、轮次、事件、目标、票型、结算和收据，也检查复核材料是否齐全；通过只说明文件与数据库一致，不代替对照录音的事实复核。
