## 业务记录与证据

每局的 `voting.json` 是独立投票业务档案，关联同目录 `dossier.json` 的 `slug`。上警/警下名单指最初竞选报名；每轮最终候选人另记，不能把退水后的候选人补集当作初始警下名单。完整座位划分可来自法官播报，也可结合全场发言顺序、人物昵称与后续票权作唯一的因果判断，推断依据另存；仍有多个合理解释时保持未知。

每轮记录游戏日、警徽/放逐类型、同日轮号、首轮/PK后/其他重投阶段、候选人、已知票权名单、逐人投向、弃票、平票名单和明确公布的当选或出局座位。PK 首轮与复投分别保存；不计算票数来反推赢家，也不从最终放逐对象倒推各人投向。警长半票等权重暂不计算。

`partial` / `complete` 只表示相对于已知票权名单的完整度。2026-10-25 按用户确认口径更新：已确认投票轮次中，有票权且没有明确投向的玩家默认记弃票，界面注明“按规则默认弃票”，原文直接报弃票则注明“原文明确弃票”。票权本身未知时仍为 `partial`，不补造整轮投票或投票人。存在冲突、目标不在候选池或数字粘连时，保留原文并结合存活、报票更正与后续流程复核；可唯一解释则修正，无法确定才待人工。

延期警长竞选只由首日白天狼人自爆中断未完竞选触发，并只延至第二天。第二天再次自爆则警徽流失，否则仍由有票权的原警下玩家投警上候选。PK重投是同日另一轮投票，不能当作跨日延期。

原文、时间范围、来源哈希、日序锚点、额外推断锚点、默认弃票的规则依据和疑点另存 `data/extractions/S22/voting/{BVID}.json`。这些材料不写进业务表。机器稿提取尚未人工回听，完整度也不等于事实已经确认。

经核对接受的更正保存在 `data/extractions/S22/voting_review/accepted.json`，包含来源哈希、更正前后字段、理由和原句；重新提取后会按来源及轮次时间定位重新应用。原文或轮次不再匹配时停止应用该更正，避免套到别轮。原视频查看结论及截图记录在同目录 `video_checks.json`，画面不足以确定的票继续保留待核。

## 数据库

迁移为 `009_voting_records.sql`，四张补充表与 `games.id` 关联：

| 表或视图 | 用途 |
| --- | --- |
| `game_sheriff_registrations` | 各次报名的上警/警下座位 |
| `game_ballots` | 每天、每种投票、每轮的候选、票权、阶段与公布结果 |
| `game_ballot_choices` | 每轮逐人投向或弃票，默认弃票依据另存磁盘 |
| `game_voting_days` | 每日投票覆盖、延期竞选、警徽流失与不适用状态 |
| `current_game_votes` | 联结日期、局次、游戏日与逐人票型的查询视图 |
| `game_endgame_phases` | 独立拍刀阶段的游戏日、行动者、明确目标集合与结算结果 |
| `current_game_endgame_phases` | 联结日期和局次的拍刀阶段查询视图 |

本次全文补录使用新表；`game_event_votes` 保留为原固定事件模型的历史入口，没有再复制同义数据。原档案与既有规则对齐的哈希继续保留。重新导入 `dossier.json` 不会删除独立投票记录。投票重导入以单局事务替换，重复执行不会累计选票；删除对局时补充记录随之删除。

拍刀数据库表由 `011_endgame_phases.sql` 新增；未明确的日期和行动者保留为空，未明确目标保留空集合。目标集合不代表刀序或全部有效击杀。原文、复核备注和来源哈希继续保存在 `endgame.json`，不复制到业务表。拍刀重导入只替换对应局的独立终局阶段，不改投票或普通夜间事件。

```sql
SELECT slug, event_date, game_number, day_number, kind, ballot_number,
       stage, voter_seat, target_seat, state
FROM current_game_votes
ORDER BY event_date, game_number, day_number, kind, ballot_number, voter_seat;
```
