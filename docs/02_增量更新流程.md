# 增量更新流程

## 窗口触发指令

用户说“增量更新”时，在当前窗口按本流程做到新增对局人工复核页；已说明采集完成则从资料核验开始。分析由当前窗口选择的模型直接完成，不通过 Codex CLI 或另起模型调用。写入最终数据、本地导出、静态上线、提交和推送按用户另行明确范围执行。

操作命令集中在[常用命令](01_常用命令.md)。日常只处理当前新增批次；历史已完成对局直接复用最终 JSON，明确修订时才按受影响字段重新取源。

## 采集与准备

1. 查看状态和计划，执行采集阶段 `collect`，展示差距并确认采集；使用已有认证设置。
2. 执行准备阶段 `process`，优先复用中文字幕，确实没有可用中文文字才转写音频。保留主 Paraformer 模型，不使用已退役的第二模型复听和旧横评链。
3. 确认本批 `input.json`、`reading.txt` 和必要原件齐备，再进入资料核验。

最终 `game.json` 中已登记的 BV/CID/分 P 代表已完成来源，旧音频或转写不存在不触发重采。当前队列在 `data/reports/<赛季>/incremental/state.json`，每局临时资料在 `data/extractions/<赛季>/incremental/<BV>_pNN_cid<CID>/`。

微博已完成日期区间使用 `data/sources/weibo_checkpoint.json`。当天未结束时，扫描完成仅表示当前可见内容已归档，次日仍补扫尚未闭合的最后一天。认证确实失败时按[登录恢复](08_微博登录态与Cookie恢复.md)处理。

## 资料核验与候选整理

当前窗口完整阅读本局文字、官方阵容与必要画面，核实座位、规范姓名、物理底牌、个人胜利阵营、日夜事件、每轮逐人票型及终局。复用已有姓名和照片绑定，新选手据官方原图名牌补充。

保存 `candidate.json`，沿用 `input.json` 的 dossier/voting 结构、slug、赛季、版型和来源 files，包含 evidence、issues，按需附独立 endgame。按[字段证据规范](03_字段证据与交叉复核规范.md)绑定本局来源，未知保持未知；物理底牌、自称、个人阵营和淘汰边分别处理。

按真实开局、入夜和天亮恢复轮次，PK、重投分别保存，未知投向不写成弃票。共用规则只计算资格，不证明实际行动；终局后未进入的行动窗口不记主动空过。能力约束查[规则推导](05_通用规则推导.md)，显示顺序查[呈现规范](07_对局信息呈现规范.md)。

## 生成人工复核页

按[复核页规范](06_复核页面生成规范.md)选身份截图与连续复盘区间，保存 `review_display.json`；截图由 `capture_bilibili_frame.py` 按实际定位取源。

执行 `review` 阶段校验候选版本、原文和字段关联，为本批生成 `data/manual_review/<赛季>_新增对局人工复核.html`，内嵌必要图片和复盘文字。用户逐局确认并选择悍跳人及是否成功；未填写继续未知，不默认无人悍跳。复核页与网站共用 `game_timeline.py`，网站不提供公开证据复核和反馈工具。

## 人工确认与最终数据

用户导出复核 JSON 后先预检。自由备注由当前窗口解释成 `masters-incremental-note-revisions-v1` 修订文件：

- 绑定 review_id、candidate_sha256、source_sha256 和原备注；games 中每条包含 patches、unresolved、bluffs。
- patches 使用指向现有 dossier/voting 字段的 JSON Pointer，附 value、note_quote 和 reason；无法唯一理解时填 unresolved，未解决项禁止应用。
- 备注明确保留成功结果为待定时，写 `success: null, success_selected: true`；未填写成功结果时写 `success_selected: false`，两者不能混用。

通过 `--note-revisions` 将修订文件交给预检与固化入口。预检失败报告具体字段，不能覆盖其他局。

明确获准写入后，执行 `finalize` 阶段，将确认后的身份、事件、票型、终局、规则结算和悍跳结果固化为 `data/games/<赛季>/<局目录>/game.json`。人工成功/失败/待定选择优先；仅处理选中局，已写入的同版本可续跑，不同版本不得静默覆盖。

## 本地导出与网站

按授权执行 `export`，从全部正式 JSON 通过共用统计生成本地静态数据，保留已有跨季范围；启动本地网站检查本批对局和受影响选手。网站不读取数据库、旧转写、历史反馈或推导指纹。正式照片以已有清单为基线，仅补新增选手。

静态成品构建、同步与上线只按明确请求执行，见[同步命令](01_常用命令.md#同步静态网站)及[发布说明](../website/static_publish/README.md)。

## 局部复核与结束

自主复核或核对外部意见时，先限定对局、字段和证据区域；仅沿具体冲突的直接依赖扩大。范围内问题有结论或明确缺口即收尾，不重审整季。外部建议仅提供意见，只有用户明确接受才修改；结构检查通过不表示每个字段都已人工确认。

按本批新增/修订局及受影响选手验证；规则或统计实现改变时运行对应回归。长期保留正式 `game.json`、必要来源定位、配置、正式照片与源码，不生成整套历史副本或验收回执。

批次完成后可删除临时截图、全文、候选、推断、复核页和已处理反馈；清理前将完成的微博日期区间及帖子 ID/日期并入 `data/sources/weibo_checkpoint.json`。未完成批次继续保留，不能按目录年代批量删除。
