# 第一步：官方媒体采集

当前任务：**拿到可追溯、可检查、可供以后转写的官方音频，并登记原始资料库。** 当前不运行转写或 AI 抽取。

所有 PowerShell 命令都从 `D:\langrensha` 执行。

## 1. 当前选择

统一入口：`scripts/collect_official_audio.py`。

- 一次处理一条 BVID/链接及一个分 P，先做好样板。
- 当前确认的官方投稿 UID 为 `19106800`；不匹配则停止，不下载音轨。
- 默认匿名、只下载独立音轨；不能取得音轨就停止，不回退整段视频。
- 默认单文件上限 200 MiB，音轨码率上限 128000 bit/s；不隐式提高上限。
- 有可见字幕则保存；没有可访问字幕也可以把已取得音轨登记原始库。
- 文件完成并通过校验后，才写入 PostgreSQL 的来源和文件表；不需要转写、身份或复核 JSON。

媒体校验使用 PyAV 打开容器和解码起始音频帧，不会加载 Whisper，也不会把音频上传到转写服务。

## 3. 采集一条新素材的标准命令

把样板 BV 换成下一条经过选择的官方 BV：

```powershell
python scripts/local_postgres.py start
.\.venv\Scripts\python.exe scripts/collect_official_audio.py BV1tj8p6REqy --auth none
```

命令内部按顺序执行：

1. 请求官方平台元数据，核对投稿 UID 和分 P。
2. 记录原始响应、标题、BV/CID、投稿时间及平台时长；尝试保存可访问字幕。
3. 请求独立音轨并下载；已有同 CID 且哈希一致的文件则复用。
4. 校验清单与原始响应、文件字节数和 SHA-256，打开音频并核对音轨、时长和起始解码。
5. 写入原始来源与文件登记，生成本次报告；不创建转写或比赛事实。

下载发生在文件阶段，原始登记发生在数据库阶段。即使数据库暂时连接失败，已下载文件也会留在原位置；数据库恢复后用 `--register-existing` 继续，不必重下。

分 P 可以明确指定：

```powershell
.\.venv\Scripts\python.exe scripts/collect_official_audio.py "https://www.bilibili.com/video/BV1tj8p6REqy/?p=1" --page 1
```

未给 `--page` 时会读取链接里的 `p`，没有则用 P1；链接和参数冲突会报错。一个媒体分 P 不必然等于一局比赛，第一步先按媒体归档，后续再划分局的起止时间。

### 从已打开的 Chrome 导出一次

1. 在平时使用的 Chrome 中登录 B 站。
2. 在同一 Chrome 打开 `chrome://inspect/#remote-debugging`，开启远程调试。
3. 若使用端口 9222，执行下列命令；端口不同则替换地址里的端口。

```powershell

```

Chrome 可能显示远程连接确认，请在 Chrome 中确认。这是 Chrome 自身的连接授权，不是新开的登录窗口。[Chrome 官方说明](https://developer.chrome.com/docs/devtools/agents/get-started/configuration)

此模式不启动新浏览器、不创建或导航标签页、不关闭已有浏览器。只请求影响 B 站主页/API 的 Cookie 并按平台域过滤，保存到 `.secrets/bilibili.cookies.txt`，不读取整个浏览器的 Cookie 列表。B 站导出还要求存在非空且未过期的 `SESSDATA`；无登录 Cookie 或导出失败时保留原文件。该检查不等于服务器已经认可登录状态，最终仍看字幕请求结果。

如果现有 Chrome 使用的是旧式 HTTP 调试端点，可显式改为：

```powershell
.\.venv\Scripts\python.exe scripts/login_session.py bilibili --cdp-url http://127.0.0.1:9222
```

连接失败会停止，不自动回退打开新窗口。浏览器配置和调试接口可能不同，地址以当前 Chrome 提供的端点为准。现代 inspect 方式与旧式命令行调试端点不能一概互换。

导出成功后，重复运行本节开头的采集命令即可。之后 Chrome 可以关闭；仅在 Cookie 到期、退出登录或被服务器判失效时重新导出，不能保证永久有效。

## 5. 产物在哪里

```text
data/
  raw/bilibili/<BVID>/p01/
    metadata.raw.json       平台原始响应
    manifest.json           来源、字幕状态、音轨大小与哈希
    audio.m4a               原始压缩音轨
    subtitle.*.raw.json     实际取得字幕时才有
  archive/                 入库的小型文本证据快照，按内容哈希保留
  reports/acquisition/     每次采集、离线检查或登记的结果报告
```

PostgreSQL 保存来源与文件登记，媒体本身仍在 `data/`。音频不再复制一份到数据库或快照目录。

本次报告中的关键状态：

| 字段/状态 | 含义 |
| --- | --- |
| `status=raw_registered` | 校验通过，原始资料登记成功 |
| `status=validated_only` | 只完成离线检查，本命令没有登记数据库 |
| `status=failed` | 失败；查看 `failed_phase` 和 `error`，不能计为完成 |
| `transcription_started=false` | 本流程没有启动模型转写 |
| `game_facts_changed=false` | 本流程没有创建或修改对局事实 |

报告只记录认证模式，不保存 Cookie 值。`.part` 是未完成下载；重新执行会从头下载，不承诺断点续传。遇到访问限制就停止并保留报告，不自动循环请求。
