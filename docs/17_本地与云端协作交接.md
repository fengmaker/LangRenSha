## 分工与交付

- 本地 Codex 负责数据生产、共享结构和最终整合；dot 在独立副本／分支开发、质检，交付补丁或提交及测试记录，由本地 Codex 审核。
- 每个文件同时只有一个编辑负责人。修改共享配置、schema、迁移、依赖或统一工作流前，先协调归属和接口；代码任务记录基线提交、分支／目录、负责文件和验收范围即可。
- 正式数据写库、合并与对外部署分别按用户授权执行；独立测试库与正式库的目标须明确区分。本文记录交接约定，不增加上述操作的授权。
- S21 由正在执行的本地任务继续负责；交接时保留进程、锁、检查点和中间结果，不重复启动转写。
- 交付记录写明最终提交、改动文件、实际执行的检查及结果、未完成的验收。凭据通过目标环境配置，代码和交接记录中只写变量名。
- 自 2026-10-27 起，用户持续授权本地 Codex 在每次完成与 dot 有关的改动后，检查并自行提交、推送至约定远端分支，方便 dot 更新；完成回复说明提交号、分支和推送结果。提交仅包含本任务相关文件；推送失败时保留本地提交并明确说明同步尚未完成。此同步授权不扩大正式写库、合并或部署范围。

## 交付资料边界

| 包 | 内容 | 去向 |
| --- | --- | --- |
| 开发包 | 代码、依赖清单、测试、少量样例及固定提交／文件清单 | Codex／dot 开发副本 |
| 网站运行包 | Next.js standalone 与 static、Node；Python API及依赖；赛季注册配置；展示图片及清单 | 对外服务环境 |
| 数据发布包 | 目标季正式对局 JSON、范围／正式规则／版型模板、已有投票旁证、悍跳发布 JSON | 独立发布环境 |
| 本地证据库 | 原音视频、完整转写、原始截图、复核材料及备份 | 本地留存和独立备份 |

在上述提交中，S22/S23 正式源数据、配置、投票旁证、两季悍跳发布 JSON 和图片清单已纳入 Git。展示资产为 `website/assets/player-photos/` 的 118 张照片及 `website/assets/bluff-frames/` 的 102 张截图，共 197,618,144 字节（约 198 MB）。无需为复现网站搬运整批 S21 证据截图。

数据发布包保留每局 `dossier.json`、`voting.json`、`endgame.json`，以及已有的 `supplemental.json`、`vote_control.json`、`formal_context.json`；旁文件也参与发布指纹。投票旁证缺失可能改变快照内容与指纹，精简包时按发布器实际读取的文件保留。

Next.js 包包含服务端功能，需 Node 运行；前端通过 API 取数据和图片。API只读 `masters_web`，展示图片仍从磁盘读取。运行配置包含 `scripts/season_config.py`、`config/seasons.json`，连接参数使用 `DATABASE_URL`、`API_BASE_URL` 等环境变量。

数据库实例、dump、凭据及 `.next` 构建产物未随 Git 交付。首次部署可从正式源重新生成网站发布库，也可恢复经过验证的网站 schema 备份；仅重新发布当前源不恢复历史发布版本。完整 `masters_web` 包含活动 game release、逐季悍跳发布及其绑定，不能以 JCMS 原始业务库替代。
