# 本地运行资源与目录整理

2026-10-22 根据三模型实测和用户的清理要求，运行资源收敛为两套环境、两种转写模型。

## 保留的运行资源

| 用途 | 环境或目录 | 入口 |
| --- | --- | --- |
| 官方媒体、微博采集与数据库 | `.venv/` | `collect_official_audio.py`、`collect_season.py`、`database.py` |
| 主转写与片段复核，共用 CUDA 依赖 | `.venv-funasr39/` | `transcribe_funasr.py`、`review_asr_clip.py` |
| Paraformer 主转写及其 VAD、标点、声纹组件 | `.models/modelscope/` | 整场转写，保持现有时间戳与分块流程 |
| Fun-ASR-Nano 小模型 | `.models/fun-asr-nano-2512/` | 对最终复盘、数字和术语疑点进行第二份转写 |
| 数据库程序与实际数据 | `.tools/postgresql/`、`.local/postgresql/` | `local_postgres.py` |
| 认证与登录状态 | `.secrets/` | 采集脚本读取，保留现状 |

Nano 目录内的 `Qwen3-0.6B/` 是它必需的文本配置和分词器，约 16 MB，不是被移除的独立 Qwen ASR 模型。Paraformer 的 VAD、CT-Punc、CAM++ 也仍是主流程依赖，不能按“不是主模型权重”删除。

`.venv-funasr39` 继续通过本地 `.pth` 复用 `D:/miniconda/miniconda-version/pkgs` 中的 PyTorch、torchaudio 和 CUDA DLL；清理没有修改该项目外目录。主转写与 Nano 不需要额外各建一套环境。

## 复核一个关键片段

在项目根目录执行，用原始音轨的既有 ASR 解码时间线选取不超过 30 秒的窗口：

```powershell
.\.venv-funasr39\Scripts\python.exe scripts/review_asr_clip.py `
  data/raw/bilibili/BV1yt7v6QE3Q/p01/audio.m4a `
  --start-ms 2037210 --end-ms 2061760 `
  --out outputs/asr_clip_reviews/BV1yt7v6QE3Q_2037210_2061760
```

也可直接传入已截好的不超过 30 秒 WAV，省略起止参数。首次加载 Nano 在本机可能需要约一分钟。脚本只加载已保留的本地模型，不下载替代模型。为保持与原转写一致的时间线，从长音轨选片时会先解码完整音轨，再按采样点截取。

输出目录包含 `clip.wav`、`transcript.txt` 和 `transcript.json`，记录原音频与片段哈希、原时间窗、实际词包和模型原文；已有非空输出目录会被拒绝。结果是待听核的第二份机器稿，没有字级时间戳或座位身份确认，不会改写主转写或写入业务事实表。

## 已移除的资源

- 独立 Qwen3-ASR-0.6B 权重与专用 `.venv-qwen-asr/`：本轮没有显示替换优势，保留测试输出与来源记录。
- 早期 Whisper base 权重 `.models/base-local/` 与专用 `.venv-asr/`：已被现有主转写流程替代，Nano 承担关键片段复核。
- pip/下载缓存、临时热词脚本、失败 Nano smoke 日志、重复 Qwen smoke 输出、安装日志及 Python 字节码缓存。

清理范围与逐项删除记录见 [清理清单](../data/reports/workspace_cleanup_20261022.json)；此前的 [目录盘点](../data/reports/workspace_inventory_20261022.json) 是清理前快照，不代表当前安装状态。字节码与少量运行缓存会在再次运行时自动生成。

本次移除文件合计约 **3.54 GiB**。清理后 Paraformer（含 VAD、标点、CAM++）和 Nano 均通过真实片段实跑，Nano 输出与此前基准完全相同；148 项采集等单元测试、2 项音频测试及 78 条历史横评校验通过。音频测试使用 `.venv-funasr39`；数据库集成测试依赖的本地服务未启动，不计入这 150 项通过测试，也没有为清理启动或修改数据库。

原始媒体、来源快照、数据库、配置、正式转写、热词对照和 78 条三模型结果保留。`data/seasons/` 与 `data/raw/` 中音频使用硬链接，不将两份目录大小相加当作两份占用，也不通过移动这些音频来压缩目录。
