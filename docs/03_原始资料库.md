# 原始资料库

原始资料库保存媒体、出处和文件登记，不要求先知道每局身份、胜负或票型。采集原件按[全流程第一步](01_赛季数据全流程.md#第一步采集原始资料)执行；登记是[第五步](01_赛季数据全流程.md#第五步核对后写入数据库)的明确写入操作，不与下载自动串联。

## 文件与数据库的分工

| 位置 | 保存内容 |
| --- | --- |
| `data/raw/bilibili/` | 独立音轨、平台原始响应、字幕和manifest |
| `data/seasons/{season}/` | 按日期、期次整理的媒体入口、字幕原件及其SRT／阅读文本 |
| `data/raw/weibo/`、`data/weibo/` | 微博原件、采集索引及已核姓名照片资料；具体分工见[data说明](../data/README.md) |
| `data/archive/` | 数据库引用的JSON／字幕等内容哈希快照 |
| `data/reports/acquisition/` | 采集结果、失败原因与媒体校验记录 |
| PostgreSQL `sources` | 来源UUID、平台、BV/CID外部键、链接、标题、作者和发布时间 |
| PostgreSQL `artifacts` | 文件UUID、所属来源、类型、路径、大小和SHA256 |
| PostgreSQL `audit_events` | 原始登记操作记录 |

大媒体留在磁盘；数据库与原始文件共同备份。`data/seasons/` 中音频可能与 `data/raw/` 使用硬链接，共用字节，不能当作独立备份。字幕的SRT／阅读TXT是同源派生格式，不是独立佐证。

## 来源标识与比赛标识

- 原媒体用 BV、CID、分P定位；一条媒体可能含多局，同局也可能有重复呈现或不同版本。
- 投稿时间保留原值，不当作比赛日。标题中的日期、阶段、版型先保留原文，核实后才进入对局事实。
- 官方作者检查核对已确认UID；标题、账号显示名和本地文件名不能单独证明来源。
- 采集或登记成功只证明该步骤的文件与来源契约，不证明整局事实、全文转写或每句话都正确。

## 登记与只读检查

在项目根目录执行；以下均是已有原件的登记示例，不是重新采集要求：

```powershell
.\.venv\Scripts\python.exe scripts/collect_official_audio.py BV1tj8p6REqy --register-existing
# 已有经过校验的manifest，也可直接登记；支持纯字幕原件
.\.venv\Scripts\python.exe scripts/database.py import-media data/raw/bilibili/BV1tj8p6REqy/p01/manifest.json
.\.venv\Scripts\python.exe scripts/database.py raw-status
```

`import-media` 登记来源与实际存在的原件，按来源外部键、文件哈希复用记录；审计可追加。它不读取身份候选、不创建业务对局，也不发布网站。`raw-status` 只读登记状态；其中 `media_validation` 是上次登记时的快照，检查当前磁盘用 `collect_official_audio.py <BV> --check-only`，不把旧校验结果当成本次复验。

## 数据库与保留边界

本机 PostgreSQL 由 `scripts/local_postgres.py start/stop` 管理，端口 `55432`，库名与schema为 `jcms`；连接配置见 `.secrets/database.json`。`.tools/postgresql/` 是程序，`.local/postgresql/` 是实际数据库，停止服务不会删除数据。迁移规则见[db说明](../db/README.md)。

转写、候选、复核旁证和[正式对局档案](04_对局档案与数据库.md)分层保留。早期转写／候选表仍有历史引用，不能为整理文档清空。`data/archive/` 的哈希文件按引用保护，清理前先查[本地资源与清理](06_本地资源与清理.md#清理入口)。
