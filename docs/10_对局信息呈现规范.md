# 对局信息呈现规范

本页统一人工复核页与网站“对局档案”的日夜、投票和角色事项展示。常规身份共用规范，特殊版型只补充实际差异；同版型跨季复用，已确认的单局裁定按本局作用域使用。事实判断查[字段规范](02_字段证据与交叉复核规范.md)，能力和合法状态查[共同规则](../config/game_rules.json)及[版型模板](05_版型规则与模板维护.md)，复核页布局与填写方式查[生成规范](09_复核页面生成规范.md)。

## 一份展示序列

共用入口为[game_timeline.py](../scripts/game_timeline.py)的`build_game_timeline(game, voting=None)`。复核页与网站对局档案统一使用这一展示序列，按返回的阶段和事项顺序渲染。

接口接受正式档案加票型，或现有公开对局字典；复用`game_inference`的角色、存活和资源推导，返回`phases`。每阶段包含轮次、夜/昼、展示名称、终局标记和有序`items`；事项为行动或票轮。展示层只读消费已核事实与推导结果，渲染器负责样式。

归档模板定义可记录的事项。展示以本局实际发生的事件和已进入的行动窗口为范围：已确认的实际时点优先，已核版型夜序其次；完整夜序待核时，按角色事项分组阅读，叫醒顺序仍标为待核。局内日次依据实际开局、入夜和天亮流程确定。

座位表按座位号排列，展示规范姓名、物理底牌和个人胜利阵营。流程使用中文事项名，人物以座位号、规范姓名和物理底牌定位；榜样、学习、傀儡和面具作为附加状态表达。稳定身份与阵营集中放在座位表，状态建立和实际变化出现在对应流程中。

## 阶段与统一阅读顺序

| 存储位置 | 显示名称 |
| --- | --- |
| `1/night` | 首夜 |
| `n/day` | 第n天白天 |
| `n/night`，n≥2 | 第n−1天夜晚 |

每个实际阶段只出现一次，顺序为首夜→第一天白天→第一天夜晚→第二天白天，依此延续。存储轮次、证据中的原称呼和意见定位保持原值，展示名称使用上表映射。投票与行动放在同一阶段内：

| 场景 | 展示顺序与边界 |
| --- | --- |
| 首日警长竞选 | 首次上警/警下名单→实际退水与候选→警长票（含PK）→当选/延期/流徽；竞选前后实际发生的死亡或技能按现场时点安放 |
| 天亮及白天 | 公布夜间出局→相应死亡技能/警徽处理→实际白天发言或技能→放逐票（含PK）→放逐结果→相应死亡技能/警徽处理；首日警长竞选与天亮公布的先后按已核流程保留 |
| 自爆中断 | 在实际中断位置显示自爆及此前已发生的票轮；延期竞选紧跟中断，次日继续原竞选 |
| 技能重投 | 首轮票型→实际触发技能/翻牌→附加发言→重投→最终结果 |
| 狼人拍刀 | 在实际发生的游戏日单列“狼人拍刀”，展示已知发起者、明确刀路和法官结算；目标集合按集合表达，已确认的刀序和有效死者分别说明 |
| 终局 | 当场结束的行动、拍刀或交牌→实际胜方；流程在现场确认的结束时点停止，夜间结束直接在该夜结算 |

同一事件只说明一次，逐人票型统一用票表表达。同类事项多次真实发生时，按时点逐次保留，包括多次警徽处理、连续死亡技能及多轮投票。

## 常规角色与公共事项

| 事项 | 显示条件与内容 |
| --- | --- |
| 狼队击杀 | 本夜有普通刀机会时，展示原目标和实际结算；确认主动空刀时写空刀；有机会而目标未知时保留待核。特殊角色接刀后，由相应角色的击杀事项表达。 |
| 女巫用药 | 按行动者存活、剩余药量和当夜用药限制确定可用窗口；同一女巫的解药/毒药合在“女巫用药”下，展示实际救人、用毒、确认空过及效果。 |
| 守卫 | 在可用窗口展示实际守护、自守或确认空过；原守护目标与反毒等实际结果分别说明。 |
| 摄梦人 | 展示实际梦游目标及已核免刀、连续梦游或夜亡连带结果；连带出局紧跟触发死亡。 |
| 预言家/通灵师 | 在实际行动窗口展示查验者、原目标和实际反馈；交换或傀儡影响在本次查验下说明。物理底牌单独保留，同夜行动与天亮公布夜死按各自时点表达。 |
| 猎人/狼王 | 本次实际出局且进入死亡技能处理时，展示资格和实际开枪、未开枪或不能开枪；紧跟相应死亡或放逐，适用资格按各自角色与本局规则核定。 |
| 白神/白痴 | 按本局底牌名称与已核规则，在实际触发处展示翻牌、离场和票权变化。 |
| 上警/警长 | 首日展示首次上警/警下、实际退水、各轮候选、票型和结果；延期当日显示“继续警长竞选”及当日实际票轮/结果；无竞争直接当选时展示当选结果。 |
| 警徽 | 初次归属在当选结果中说明；后续实际移交、撕毁或流失紧跟相关出局或现场处理。 |
| 夜间出局 | 在实际公布或终局结算位置展示平安夜、死者及已核原因；受击、死亡、公布和延迟离场分别按实际时点表达。 |
| 放逐 | 展示实际投票及最终放逐；两轮平票时保留两次票型，并写“平安日，无人被放逐”。 |

页面展示实际行动、确认空过和本局必要的待核事项。不可用、未举行、资源耗尽等归档状态保存在档案及推导中；有真实机会且关系存活、信息或胜负的未知行动，以具体问题标注待核。实际违规行动、原目标和DQ裁定按现场经过展示。

## 票型规范

- 票表放在对应游戏日的警长竞选或放逐步骤中。普通放逐票标题使用“放逐投票”，日次由所属白天标题说明；额外轮次标明“PK复投”或“技能重投”。
- 警长、放逐、PK和技能重投逐轮保留，使用本轮候选、票权和实际投票者；每张票表列出投票者与投向，结果随对应票轮呈现。
- 弃票分别标识为“原文明确弃票”和“按规则默认弃票”。默认弃票限于已确认举行、票权名单已核的票轮；投向未记录、票权未知和整轮缺失分别保留具体缺口。
- 警长半票等票重按当轮已核持徽与适用规则说明。逐人选票按实际张数保留，原始票数、加权票力和宣布结果分别表达。
- 保留宣布结果和技能后的最终结果，分别表达高票者、最终放逐者及交换后的实际出局者。冲突回到本局明确结论或待核问题。
- 首次报名、退水后的候选、各轮候选分别保存。首夜死者在竞选后才公布时，竞选实际票型按现场经过保留，后续票权按已核死亡与资格计算。
- 延期竞选由首日自爆中断未完竞选触发，延至次日继续；次日再次自爆则展示流徽，否则使用仍有票权的原警下玩家投票。PK、技能重投按各自实际触发单列。
- 独立票型档案中的真实票轮，即使固定事件槽缺失，也按相应竞选或放逐结果定位展示。正常白天的放逐票型缺失时，按本日流程列出待补录问题；中断及终局以现场边界限定检查范围。

## 实现与验收

呈现规则集中维护在共用展示入口，复核页和网站按返回序列渲染。新增版型只补充实际差异，复用现有存活、资源与票权推导；终局截断在序列生成时完成。正式底牌、事件原值、投票和人工结论保留各自事实与来源关联。

针对变化局核对阶段顺序、角色触发、票轮前后关系、终局停止及源数据保持原值。相关验证覆盖混血儿首夜一次且阵营相邻、猎人实际出局触发、延期竞选、王子重投、必要未知可见、独立票轮保留和夜间交牌直接结束；按本次变更运行对应样例与回归。网站发布按用户授权范围执行，发布后核对对应页面与API。
