# 常用命令

## 当前窗口指令

| 直接对助手说 | 执行范围 |
| --- | --- |
| `增量更新` | 按[增量流程](02_增量更新流程.md)采集、整理，做到新增对局人工复核页 |
| `采集已完成，继续增量更新` | 从资料核验继续，做到人工复核页 |
| `应用复核结果：<复核JSON路径>` | 预检反馈与备注，将确认结果写入本批正式 `game.json` |
| `导出并检查本地网站` | 导出本地静态数据，验证本批对局及受影响选手 |
| `同步静态网站` | 构建、同步独立发布仓库，提交推送并核对部署与线上版本 |
| `提交并推送本地改动` | 检查所述范围，提交并推送源码仓库现有 `origin/main` |

增量更新的分析由当前窗口选用的模型直接完成。写入结果、本地导出、静态上线、源码提交推送按明确请求的范围执行；只说“增量更新”默认做到人工复核页。

## PowerShell 准备

以下命令在项目根目录执行，赛季以 `S23` 为例。反馈文件名、BV、日期和自定义路径按实际替换。各节按需使用。

```powershell
Set-Location D:\langrensha
```

## 增量更新

查看本地状态和执行计划：

```powershell
.\.venv\Scripts\python.exe scripts/workflow.py status --season S23
.\.venv\Scripts\python.exe scripts/workflow.py plan --season S23
```

采集会先展示差距并确认；准备阶段优先使用已有中文字幕：

```powershell
.\.venv\Scripts\python.exe scripts/workflow.py run --season S23 --stage collect
.\.venv\Scripts\python.exe scripts/workflow.py run --season S23 --stage process
```

由当前窗口按[增量流程](02_增量更新流程.md#资料核验与候选整理)完成 `candidate.json`、截图和 `review_display.json` 后，再生成复核页：

```powershell
.\.venv\Scripts\python.exe scripts/workflow.py run --season S23 --stage review
```

输出：`data/manual_review/S23_新增对局人工复核.html`。统一入口支持 `--bvid` 限定准备或复核的对局。

## 复核反馈与写入

将页面导出的 JSON 放到 `data/manual_review/feedback/`，先预检：

```powershell
.\.venv\Scripts\python.exe scripts/apply_incremental_review.py "data/manual_review/feedback/复核结果.json" --season S23
```

有自由备注时，先由当前窗口按[备注修订协议](02_增量更新流程.md#人工确认与最终数据)解释为结构化修订；预检和写入命令均追加 `--note-revisions "修订文件路径"`。明确要求写入后执行：

```powershell
.\.venv\Scripts\python.exe scripts/workflow.py run --season S23 --stage finalize --review-export "data/manual_review/feedback/复核结果.json"
```

仅重新生成已准备的复核页，或读取仍保留候选的指定已应用对局：

```powershell
.\.venv\Scripts\python.exe scripts/game_review_page.py --season S23
.\.venv\Scripts\python.exe scripts/game_review_page.py --season S23 --bvid BV1RQx364EaF --output data/manual_review/S23_单局复核.html
```

## 本地网站

导出全部正式数据、只读验证、启动预览：

```powershell
.\.venv\Scripts\python.exe scripts/workflow.py run --season S23 --stage export
.\.venv\Scripts\python.exe scripts/workflow.py run --season S23 --stage verify
.\.venv\Scripts\python.exe website/run.py
```

`export`、`verify` 使用全部赛季的最终数据，`--season` 不缩小导出范围。预览地址：<http://127.0.0.1:3000>。安装与网站说明见 [website](../website/README.md)。

## 同步静态网站

只构建并检查本地成品：

```powershell
.\.venv\Scripts\python.exe website/static_publish/build_static.py
```

明确要求同步上线时直接执行：

```powershell
.\.venv\Scripts\python.exe website/static_publish/sync_pages.py
```

同步命令已包含构建，无需先单独构建；加 `--check-only` 则只构建并检查本地成品。默认输出为 `tmp/pages-preview/langrensha-site`，发布仓库为 `D:\langrensha-site`，线上为 <https://fengmaker.github.io/langrensha-site/>。该命令会提交并推送发布仓库 `main`；源码仓库的提交推送另按明确请求执行。参数和失败处理见[静态发布说明](../website/static_publish/README.md)。

## 微博登录恢复与补采

日常采集先复用已有 Cookie，登录失效时自动尝试一次恢复。需要单独刷新时：

```powershell
.\.venv\Scripts\python.exe scripts/login_session.py weibo --refresh
```

只查看采集差距，或在本次采集已获准时直接续跑：

```powershell
.\.venv\Scripts\python.exe scripts/update_incremental.py --season S23 --check-only
.\.venv\Scripts\python.exe scripts/update_incremental.py --season S23 --yes
```

使用自定义 Cookie 文件时，刷新和采集必须指向同一文件：

```powershell
.\.venv\Scripts\python.exe scripts/login_session.py weibo --refresh --cookies-file .secrets/weibo-other.cookies.txt
.\.venv\Scripts\python.exe scripts/update_incremental.py --season S23 --yes --weibo-cookies-file .secrets/weibo-other.cookies.txt
```

单独补采指定微博日期范围（不会自动启动登录助手，必要时先刷新）：

```powershell
.\.venv\Scripts\python.exe scripts/collect_weibo_archive.py --since 2026-11-06 --until 2026-11-07
```

复用已经开启远程调试的现有 Chrome 时，使用浏览器提供的完整本机 CDP 地址：

```powershell
.\.venv\Scripts\python.exe scripts/login_session.py weibo --cdp-url "替换为Chrome显示的完整本机CDP地址"
```

登录恢复顺序、人工验证和完成标准见[微博登录态与 Cookie 恢复](08_微博登录态与Cookie恢复.md)。
