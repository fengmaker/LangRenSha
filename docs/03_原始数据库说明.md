# 原始数据库说明

2026-10-22 更新：源文件登记方式继续使用本页说明；逐局业务数据已按用户要求改为统一人物与固定事件槽位，见 [对局数据库与版型模板](09_对局数据库与版型模板.md)。该业务结构不再保存证据、完整转写片段、版本或审核状态。下文有关“后续再推进”的表述记录原始资料采集阶段的安排。

当前“做好数据库”首先指：把原始媒体、出处和文件状态保存成可靠的资料库。它不要求先知道每一局的身份、胜负和票型。

## 1. 文件与 PostgreSQL 各存什么

| 位置 | 保存什么 | 是否需要转写 |
| --- | --- | --- |
| `data/raw/bilibili/` | 下载的独立音轨、原始接口响应和清单 | 不需要 |
| `data/seasons/S22/` | 按日期、周次及赛事阶段命名的音频入口、字幕原件、SRT、阅读文本和复核总目录 | 使用平台现成字幕，无需本地模型 |
| `data/archive/` | 入库时的 JSON/字幕等文本快照，保留不同内容版本 | 不需要 |
| `data/reports/acquisition/` | 每次执行是否成功、失败在哪一步、媒体校验结果 | 不需要 |
| PostgreSQL `sources` | 来源 UUID、平台、BV/CID 外部键、链接、标题、投稿账号和平台发布时间 | 不需要 |
| PostgreSQL `artifacts` | 文件 UUID、所属来源、类型、路径、字节数和哈希 | 不需要 |
| PostgreSQL `audit_events` | 原始登记发生过的操作记录 | 不需要 |

“原始资料库”就是这些文件与登记共同组成的库。大音频不塞进 PostgreSQL，数据库和 `data/` 应一起保存与备份。

S22 整季素材从[归档说明](../data/seasons/S22/README.md)进入。整理目录中的音频与原始目录使用硬链接，共用同一份媒体字节；它是阅读入口，不能视为另一份备份。字幕不同内容版本则作为独立文本证据保留。归档周次、标题日期和阶段候选记录在来源的 `metadata.collection_context`，未写成已核验对局事实。

PostgreSQL 仍使用现有的 18.6，本机地址 `127.0.0.1:55432`，库名/schema 均为 `jcms`。本轮不重新选库、不重建库、不继续扩张网站业务表。

## 2. 独立的原始资料入口

首选第一步统一命令：

```powershell
.\.venv\Scripts\python.exe scripts/collect_official_audio.py BV1tj8p6REqy
```

如果素材已经下载好，用：

```powershell
.\.venv\Scripts\python.exe scripts/collect_official_audio.py BV1tj8p6REqy --register-existing
```

也可直接导入经过校验的媒体清单：

```powershell
.\.venv\Scripts\python.exe scripts/database.py import-media data/raw/bilibili/BV1tj8p6REqy/p01/manifest.json
.\.venv\Scripts\python.exe scripts/database.py raw-status
```

`import-media` 只登记来源、原始清单、元数据、音频和实际取得的字幕。它不读取转写/身份候选，不创建比赛、选手或积分，也不发布任何记录。相同来源外部键和相同文件哈希会复用已有记录；操作审计仍可追加。

`raw-status` 只显示原始来源和原始文件数，不把 ASR、AI 候选和统计混进来。其中 `media_validation` 是上次登记时的校验快照；需要检查磁盘现在是否仍完好，执行统一入口的 `--check-only`。

## 3. 标识与日期

- 原始媒体用 `BV + CID` 标识，另外保存分 P；它不等于比赛 ID。
- 一条媒体可以包含多局，多个媒体也可能是同一局的不同版本，后续解析时再建立对应关系。
- 平台投稿时间按原始值保存，不当作比赛日期。
- 标题中写的赛季、日期、阶段和配置先保留在原文；不能因为下载成功就变成已核验比赛事实。

现阶段的官方检查是投稿 UID 与已确认 UID 匹配，不声称仅凭标题或账号名能鉴定任何来源。

## 4. 与后两步的边界

| 数据层 | 内容 | 当前安排 |
| --- | --- | --- |
| 原始资料 | 媒体、链接、元数据、文件登记与校验 | **本轮推进** |
| 转写与候选 | 模型文字、说话人候选、AI 提取 JSON、证据定位 | 试验成果保留，后续再做 |
| 对局事实 | 经核对的座位、选手、身份、票型、发言、结果 | 后续形成，不用猜测补齐 |

此前试验已经向数据库加入过转写、12 座候选和比赛草稿，磁盘上也有全文与修订样本的 JSON/SRT，以及 `pilot.review.json`。这些小型输入及数据库引用的快照继续保留；未入库、已被修订样本替代的初版 ASR 两个文件已清理。真实样板仍未正式发布，当前不要求你继续人工复核这些候选。目录用途和其他清理结果见 [data 目录说明](../data/README.md)。

以后第二步字段稳定，再完善第三步的业务表及通用导入；完整发言、逐轮投票和复盘表暂不提前铺开。

## 5. 运行与保留

```powershell
python scripts/local_postgres.py start
.\.venv\Scripts\python.exe scripts/database.py raw-status
python scripts/local_postgres.py stop
```

停止不会删数据。`.local/postgresql/` 是数据库数据，`.tools/postgresql/` 是便携程序，`.secrets/database.json` 是本机连接配置。当前为本机开发环境；生产账号、备份恢复演练和公开网站部署另行安排。

以后需要查看旧的完整复核/发布 CLI 时，可查[此前数据库试验说明](archive/2026-10-20/数据库与单视频完整流程.md)，当前不按旧文中的“下一步人工复核”推进。
