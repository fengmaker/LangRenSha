# 中文狼人杀音频的本地 ASR 候选（2026-10-22）

本文为实测前调研记录，以下“尚未安装、下载、运行”描述当时状态。随后已完成 Paraformer、Qwen3-ASR-0.6B 与 Nano 的 [实际对照](../01_赛季数据全流程.md#历史实测与既有成果)，并在清理后仅保留 Paraformer 与 Nano；当前资源见 [运行说明](../06_本地资源与清理.md)。

## 结论

值得用同一批短音频对照三条路线：Qwen3-ASR-0.6B（通用识别质量候选）、Fun-ASR-Nano-2512（支持显式专名热词的候选）和 SenseVoiceSmall（轻量基线）。它们的官方公开基准都不能代替对狼人杀音频的实测：游戏录音里的座位号、角色名、规则词、多人插话和游戏事件词与公开朗读、会议语料不同。模型换代也不保证胜过现有 SeACo-Paraformer 流程。

建议先试 Qwen3-ASR-0.6B 与 Fun-ASR-Nano；SenseVoiceSmall 可用来提供轻量基准。Qwen3-ASR-1.7B 可以留作可选质量上限对照：在 6GB 显存的笔记本上不应假设能稳定加载或处理长段音频。部署前应在独立环境用小批量实测峰值显存。以下不代表已安装、下载、运行或微调任何候选模型。

## 候选和能力边界

|---|---|---|---|---|
| **Qwen3-ASR-0.6B** | 官方支持中文等30种语言及22种中文方言；离线/流式共用模型，可转写长音频。官方公开表格报告了 WenetSpeech、AISHELL-2、Fleurs 等语料结果。([模型卡](https://huggingface.co/Qwen/Qwen3-ASR-0.6B)、[仓库](https://github.com/QwenLM/Qwen3-ASR)) | 官方本地 `qwen-asr` Python 接口为 `transcribe(audio, context="", language=None, return_time_stamps=False)`；`context` 是作为 system 消息传入的上下文字符串，可按音频传一个字符串或列表。它没有单独的 `hotwords` 参数；把游戏术语写进上下文是可测的提示，不等于保证声学解码偏置成功。([接口实现](https://github.com/QwenLM/Qwen3-ASR/blob/main/qwen_asr/inference/qwen3_asr.py)) | 需额外加载 `Qwen3-ForcedAligner-0.6B` 并请求 `return_time_stamps=True`。这是把识别出的文字与音频强制对齐以产生时间点；ASR 本身不直接输出词级时间戳。对错误识别的文本做对齐不会把它变成正确转写。([模型卡](https://huggingface.co/Qwen/Qwen3-ASR-1.7B)、[对齐器用法](https://github.com/QwenLM/Qwen3-ASR/blob/main/qwen_asr/inference/qwen3_asr.py)) | 官方代码当前将 ASR 输入按最多 1,200 秒切块；启用时间戳时最多 180 秒一块。模型卡概述称对齐器可处理至 5 分钟，和 Python 包当前 180 秒切块设置口径不同，实用上先按 3 分钟以内对齐块设计。Qwen 官方建议新建隔离 Python 3.12 环境、使用 `qwen-asr`；FlashAttention 2 对长输入和大批次有帮助，较小 `max_inference_batch_size` 可降低 OOM 风险。([切块常数](https://github.com/QwenLM/Qwen3-ASR/blob/main/qwen_asr/inference/utils.py)、[环境与推理指南](https://huggingface.co/Qwen/Qwen3-ASR-1.7B)) |

| **Fun-ASR-Nano-2512** | 官方列为约 800M 参数，训练数据规模及中文方言/口音覆盖为发布方声明；官方基准包括 AISHELL、Fleurs、WenetSpeech。它是端到端 ASR 大模型。([官方仓库与基准](https://github.com/QwenAudio/Fun-ASR)) | FunASR Python 路径接受 `model.generate(..., hotwords=["术语一", "术语二"], language="中文", itn=True)`：参数名为复数 `hotwords`，值为字符串列表。这是最直接的专名提示对照。不要把 SeACo 的 `hotword` 字符串参数或 Qwen 的 `context` 提示当成同一种接口。([官方用法](https://github.com/QwenAudio/Fun-ASR/blob/main/README.md)、[FunASR API 边界说明](https://github.com/modelscope/FunASR/blob/main/docs/python_api.md)) | FunASR 路径下 ModelScope 官方 checkpoint 当前带完整 CTC 权重，可提供模型自身的 CTC 字符/词时间戳；官方 README 记录的旧 Hugging Face checkpoint 修订则没有这些权重，需核对所取 hub 和 revision。它不是 Qwen 那种显式接收任意给定文本的 forced-aligner 接口。([checkpoint 能力说明](https://github.com/QwenAudio/Fun-ASR#capability-boundaries)、[API 输出说明](https://github.com/modelscope/FunASR/blob/main/docs/python_api.md)) | FunASR 高层 `AutoModel` 可接 FSMN-VAD 自动分段；官方示例限制单段 30,000ms。不要把 `AutoModelVLLM` 的单次长音频输入当成无限长：官方 README 提醒该路径单次解码，数分钟录音可能截断，应先 VAD 切段或使用高层带 VAD 的 `AutoModel`。官方 Transformers 原生路径的示例在 Linux/Python 3.12 CPU 环境验证，首次加载约 1.66GB 权重；这不是 6GB GPU 显存保证，也不证明它能直接装入现有 Python 3.9 环境。([VAD/长音频说明](https://github.com/QwenAudio/Fun-ASR/blob/main/README.md)、[Transformers 环境记录](https://github.com/QwenAudio/Fun-ASR/blob/main/examples/transformers/README.md)) |

### 显存和兼容性判断

参数量乘两字节只是 BF16/FP16 权重的**粗略下限估算**：Qwen 0.6B 约 1.2GB，Qwen 1.7B 约 3.4GB，Fun-ASR-Nano 0.8B 约 1.6GB。实际推理还占用音频特征、KV/临时缓存、运行时和显卡桌面资源。Fun-ASR 官方所报 1.66GB 是其 Transformers checkpoint 首次下载体积，不是峰值显存。没有找到这些官方资料对 RTX 3060 Laptop 6GB 作出的稳定运行承诺，因此 0.6B、Nano 和 SenseVoice 都应先小批量量测，1.7B 尤其不能保证。

Qwen 官方建议 Python 3.12 隔离环境；Fun-ASR 官方原生 Transformers 示例同样按 Python 3.12/Linux 准备。当前项目已有 Python 3.9.23、PyTorch 2.5.1+cu118、FunASR 1.4.16，可作为评估参照，但不能据此认定新系列已兼容当前环境。后续试用时，应先在独立环境验证加载与推理，不要覆盖现有 SeACo 环境。([Qwen 环境建议](https://huggingface.co/Qwen/Qwen3-ASR-1.7B)、[Fun-ASR 原生环境](https://github.com/QwenAudio/Fun-ASR/blob/main/examples/transformers/README.md))

## 对官方基准的解读

Qwen 模型卡报告 0.6B/1.7B 在 WenetSpeech、AISHELL-2、Fleurs 等数据集上的 WER；Fun-ASR 报告 AISHELL、Fleurs、WenetSpeech 等测试集的 WER；SenseVoice 展示普通话、粤语等公开语料对比。它们的测试集、解码、文本规范化和模型运行路径不完全相同，因此不要把来自不同表格的数字排成一张“谁最好”的榜单。狼人杀音频还需要验证角色口令、座位号、语速、重叠说话和专有名词。([Qwen 基准](https://huggingface.co/Qwen/Qwen3-ASR-1.7B#evaluation)、[Fun-ASR 基准](https://github.com/QwenAudio/Fun-ASR#performance)、[SenseVoice 基准](https://github.com/QwenAudio/SenseVoice#benchmarks))

本项目 37 分钟受控试验中，34 词和 343 词两种词表的表现都有好有坏；不能据此得出“大词表更准”。另外，本地实现对超过 50 个候选词会进入词筛选分支（主代理已检查本地 SeACo-Paraformer 代码）；这是可能影响对照的待验证机制，不是已经确认的主因。对狼人杀音频，较稳妥的实验起点是保留完整总词库，再按板型、角色和环节抽出 20–40 个相关词作为单次小词包，并与无热词、不同候选规模同时对照。

## 5–10 分钟小样本对照方案

这里的“5–10 分钟”指总测试音频时长。选择同一局中分散的若干片段（例如 8–12 段、每段约 30–60 秒），覆盖常规发言、语速快或抢话、术语/人名、座位数字，以及投票/放逐、狼人袭击、预言家查验、女巫用药、猎人开枪等关键事件。保留每段在原文件中的起止时间和环节标签；不要只选对模型容易的清晰片段。

对比现有 SeACo-Paraformer 流程、Qwen3-ASR-0.6B、Fun-ASR-Nano 和 SenseVoiceSmall。各模型使用同一批原始片段，记录模型/checkpoint revision、解码与 VAD 设置、热词/context、时间戳模式、速度和峰值显存。先做一次无提示词基线；再对明确支持的接口各做一次术语提示实验（SeACo 用它自己的 `hotword` 接口，Nano 用 `hotwords=[...]`，Qwen 用 `context="..."`，SenseVoice 无通用热词）。比较时同时保留 raw 输出和经过 ITN/标点后的文本；统一后处理规则后再算分。

指标建议：

- **总体 CER**：用经人工听辨校订的参考文本计算字符错误率，明确简繁、标点、数字写法、语气词和口头重复的归一化规则。WER 可附录报告，不作为中文主指标。
- **专有词准确率**：单列角色/玩家名、术语和专名的正确率及错词例子；把错认成另一个合法术语与完全漏词分开记录。
- **座位数字准确率**：统计座位数字的 exact match、漏报、误报和相邻座位混淆（如 6/7），不要只看总体 CER。
- **事件/动作识别**：对投票、出局、击杀、守护、验人、救/毒、开枪、遗言等词项统计 precision/recall/F1，同时检查否定、施受者和座位号是否识别正确。
- **工程记录**：冷启动/热启动时间、每段耗时或 RTF、峰值显存、OOM/截断/空转写次数；质量和资源开销分开看。

参考真值需要人按音频复听并校订，最好对模糊片段由第二位听者复核；有比赛日志或字幕时只能用作核对线索，因为它们可能漏掉口语细节或与音频不同步。多个模型一致只说明输出一致，不自动等于真值；模型有分歧时也不能用多数票替代人工确认。先用这批样本判断是否值得扩大到一局完整录音，再决定是否安装、固定版本或调整项目实现。

## 微调支持

Qwen 官方仓库提供 Qwen3-ASR 的 JSONL 音频/文本监督微调脚本；Fun-ASR 官方提供 ChatML 格式的 Nano 微调配方，可选择冻结编码器/适配器或微调解码器；SenseVoice 官方仓库提供 FunASR 训练脚本。([Qwen 微调配方](https://github.com/QwenLM/Qwen3-ASR/tree/main/finetuning)、[Fun-ASR 微调说明](https://github.com/QwenAudio/Fun-ASR/blob/main/docs/finetune.md)、[SenseVoice 微调说明](https://github.com/QwenAudio/SenseVoice#finetune))

这是后续有人工真值、训练预算和独立验证集时的路线，不是 5–10 分钟试验的前提。一个很小的样本集容易过拟合；应先证明模型在留出的真实片段上确有稳定收益，再估算训练所需显存和数据量。

## 主代理核对：本地实现中可先验证的改进点

已读取项目实际安装的 FunASR 1.4.16 [SeACo 解码实现](../../.venv-funasr39/Lib/site-packages/funasr/models/seaco_paraformer/model.py)：`_seaco_decode_with_ASF` 默认 `nfilter=50`，当候选总数（含模型附加项）超过 50 时，先由 ASF 打分筛选再做上下文解码；代码用 `hotword_scores[0]` 聚合出同一批的筛选列表。34 词与 343 词因此走不同筛选分支，后续可测试候选规模和批次组成是否影响“警徽/守卫”等词。**这只是实现事实与实验假设，不能据此确定本次退步的原因。**

当前 SeACo `inference` 调用该函数时只传 `hw_list`，没有转发外部的 `nfilter` 或 `seaco_weight`；仅在 `model.generate` 增加同名参数，不应假定会改变这条解码路径。若以后要调权重或筛选数，需要先验证参数确实生效。本轮未修改安装库或任何推理实现。

现有[转写脚本](../../scripts/transcribe_funasr.py)的约十分钟外层块用于处理和检查点，内部 VAD 已配置 `max_single_segment_time=30000`。因此不应把外层块当成模型一次理解十分钟的语义上下文，也不能承诺只把 `--chunk-seconds` 改小就能提高识字准确率。优先检查内部语音切点、句首句尾是否完整，再试有限上下文或重叠，并核对去重和原始时间偏移。

建议保留当前总词库，运行时按“本局角色＋板型＋所处环节”选择小词包；20–40 词只是实验起点，应与原 34 词、343 词以及真正关闭热词的路径比较。模型代码对 `hotword=None` 和空字符串走的分支不同，空词表不一定等同关闭热词，基线应明确核验。

识字准确率、标点、时间戳和说话人归属分别评价：CT-Punc 或对齐器改善断句/时间位置，不会自动把“警卫”改对；CAM++ 标签变化也不能当作识字变准。LLM 可生成带来源的校订候选，不应依据游戏逻辑补座位、身份、技能目标或否定词。模型分歧最适合用于挑出需要回听的片段。

## 主代理补充：其他候选

### Whisper 大模型作为独立对照

当前项目早期脚本默认是 Whisper `base`，不能用它的识别表现代表整个 Whisper 系列。官方 `turbo` 为 `large-v3` 的速度优化版本；官方原实现列出的显存约为 turbo 6GB、large 10GB，不能直接按这些数估算不同推理后端。([Whisper 官方模型说明](https://github.com/openai/whisper#available-models-and-languages))

可以把 `faster-whisper` 的 `large-v3` 或 `turbo`、单批次及 INT8/FP16 混合量化作为另一家族的对照。项目官方给出 `compute_type="int8_float16"` GPU 用法，其 README 的 2926MB 显存基准测的是 **large-v2**、特定显卡与设置，不是本机 large-v3 的保证。当前新版 CTranslate2 依赖 CUDA 12/cuDNN 9，而项目原 PyTorch 为 cu118；两个运行时要求需要分别处理，不能直接覆写旧环境。([faster-whisper 官方用法、基准和依赖](https://github.com/SYSTRAN/faster-whisper))

### FireRedASR2-AED 作为带时间戳的中文候选

发布方提供中文/方言识别、词级时间戳和置信度输出，并给出直接推理和 VAD 系统用法。官方 FAQ 对 AED 建议输入不超过 60 秒，LLM 版不超过 40 秒；长音频需要切段。未在这些资料中找到 RTX 3060 Laptop 6GB 的运行保证，因此列为后续候选而非已验证替代。置信度也不能替代对座位号和事件目标的核验。([FireRedASR2S 官方仓库](https://github.com/FireRedTeam/FireRedASR2S))

### 付费录音识别 API 作为可选外部对照

阿里云当前总览把 `qwen-audio-3.0-asr-flash-filetrans` 列为支持热词、Prompt 上下文和说话人分离的非实时录音模型；名字相近的 `qwen3-asr-flash-filetrans` 是另一系列，不能混用能力或参数。若以后选择付费云服务，应在同一组有人工参考的短音频上比较，并记录实际模型快照、参数和费用。([阿里云官方语音识别总览](https://help.aliyun.com/zh/model-studio/asr-model/))

本轮仅研究与保存建议，没有下载模型、安装依赖、运行新模型、调用收费 API 或上传音频。
