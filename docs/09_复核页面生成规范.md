# 复核页面生成规范

逐局复核页采用已确认的[单局样页](../data/manual_review/S23_逐局复核_单局样例.html)。日夜和票型的顺序、角色触发与显示条件统一按[对局信息呈现规范](10_对局信息呈现规范.md)执行。

## 统一交付目录

人工复核页面、待核清单和用户导出的反馈统一放在`data/manual_review/`，从[人工复核首页](../data/manual_review/index.html)进入。按赛季、用途命名页面；历史待核槽位和新增对局分别列出。

用户导出的JSON保存到该目录的`feedback/`后交回当前窗口。原始媒体、截图、分析候选与应用回执按各自来源目录保存，页面内嵌所需截图和复盘文字。

## 输入先准备好

1. 当前窗口模型完成本局座位、规范姓名、物理底牌、个人阵营、日夜、票型及终局整理。复用已采文字和已有结论；分析入口见[增量流程](08_增量更新流程.md)。
2. 同时处理选手图片：通过现有照片索引复用选手与图片绑定；新选手从已采集的官方微博原图读名牌，新建选手记录并绑定图片。
3. 选择能够核对本局姓名与真实物理底牌的白天发言截图或连续复盘身份页，确认画面视角和姓名牌，保存原图。
4. 定位连续复盘区间，选定起止时间。分析可读全文，交付页面只内嵌这个复盘区间的文字。

日常复用已有来源和绑定，按本次对局需要补充资料。版本检查由意见导入和入库程序处理，实际失败时说明原因。

## 单局显示资料

在对应增量目录保存`review_display.json`；也可通过`game['review_display']`直接传给构建器。它记录页面选材：

```json
{
  "identity_frames": [
    {"source_path": "项目内的本局身份截图.png", "caption": "本局姓名与真实身份"}
  ],
  "recap": {
    "source_path": "本局已有中文字幕或完整转写.json",
    "start_ms": 5812230,
    "end_ms": 5853910
  }
}
```

路径为项目相对路径。截图按需要选择一张或多张，复盘区间须有连续文字；资料齐备后生成页面。来源记录、完整字幕和分析资料保存在本机。

## 固定页面顺序

| 区块 | 展示要求 |
| --- | --- |
| 本局概况 | 日期、局次、版型、胜方和按需打开原视频的链接 |
| 身份截图 | 放在上方，内嵌原图，点击放大；离线打开可查看 |
| 座位身份与悍跳复核 | 按座位排列全部12席，展示姓名、物理底牌、个人阵营；用一行控件选择悍跳人及是否成功 |
| 对局流程 | 首夜、白天、后续夜晚依次呈现；投票放在对应的警长或放逐步骤内 |
| 复盘转写 | 默认可折叠，仅包含选定的连续复盘区间 |
| 我对本局的复核意见 | 本局备注和“已复核此局”；选择及意见自动保存，可导入导出 |

页面按上述区块纵向排列。批量页面每次显示一局，用顶部选局、上一局和下一局切换。

唯邻是从的座位表将物理底牌与个人胜利阵营分开显示：傀儡保留原底牌，个人胜利阵营跟狼人。流程在实际时点展示傀儡选择；没有证据确定首夜先后时保留待核，不按模板槽位推断睁眼顺序。傀儡不带刀；傀儡平民不显示独立技能事项，傀儡神职只有实际发动技能时才在该技能事项说明影响。正常淘汰结算时，傀儡存活不能判好人胜；狼人屠边不将傀儡计入原底牌所属边。已确认交牌认输则按实际终局结束。详细规则、槽位顺序和发布显示验收见[唯邻是从详细呈现规则](10_对局信息呈现规范.md#neighbor-puppet-display)。

## 悍跳与成功选择

默认用一行控件选择悍跳人（全部12席可选，默认未选择），再选择是否成功（未填写、成功、失败、待定；选人后启用）。另有“本局无人悍跳”复选框，选中后禁用悍跳人控件，并在导出和草稿中将12席全部记为`decision=no, success=""`；这表示明确确认全局无人悍跳，与未填写的空白不同，也不能同时填写悍跳人。取消后恢复可填写状态并清除这组全席`no`。

默认每局最多一名狼悍跳；选定狼人悍跳后，其余未选中的狼人按未悍跳处理，不逐个要求确认。多狼悍跳或其他座位仍待定等例外由备注说明并优先采用，保留添加悍跳人的控件。整局未选人且未确认无人悍跳时，继续保留未知。

## 生成入口

统一使用[game_review_page.py](../scripts/game_review_page.py)，HTML与交互模板为`scripts/templates/game_review.html`及`game_review.js`。

```powershell
# 生成所有已分析、尚未应用的新局
.\.venv\Scripts\python.exe scripts/game_review_page.py --season S23

# 指定单局；可读取已应用结果作复核
.\.venv\Scripts\python.exe scripts/game_review_page.py --season S23 --bvid BV1RQx364EaF --output data/manual_review/S23_逐局复核_单局样例.html
```

构建器读取现有候选、显示选材和文字，生成离线HTML，默认输出`data/manual_review/<赛季>_新增对局人工复核.html`。各赛季使用同一`render_review_page(games, output, season=...)`布局接口，按各自候选适配和实际对局范围生成。

历史待核槽位页仍由各自生成入口维护；当前`日夜待核槽位人工复核_20261030.html`由`scripts/build_pending_slot_review.py`从`日夜深度复核剩余待核_20261030.csv`及共享复核报告生成。页面答复保存在浏览器本地草稿，使用页面“导出复核结果”保存到`data/manual_review/feedback/`；重建前先导出答复。生成器按`source_fingerprint`区分草稿，仅迁移问题对象未变的题目；只更新唯邻是从静态规则旁注时，必须保持复核数据、题目编号和指纹不变。

用户已确认且已应用的事项从剩余待核清单移出，原问题和确认依据归档到`data/manual_review/feedback/`。连续重建须保留已有草稿迁移链，只按各版本间未变题目的交集恢复填写；已解决或内容变化的题目不带回新版。2026-10-31已结清`DN-197`（S22 2026-08-07第2局首夜12号大卫空守），剩余75题保持原内容。

## 意见文件与应用

导出格式为`masters-incremental-review-v2`。每局包含对局身份、版本字段、`reviewed`、`note`和完整对应本局所有座位的`bluffs`：

```json
"bluffs": [
  {"seat": 1, "decision": "yes", "success": "success"},
  {"seat": 2, "decision": "", "success": ""}
]
```

`decision`为`"" / yes / no / uncertain`；`success`为`"" / success / failure / uncertain`，仅`yes`座位保存成功项。页面保存完整快照；全席`no`恢复时自动勾选“本局无人悍跳”。导入先合并明确选择与备注例外，再按默认名单口径把未选中的狼人记为`no`；整局未填写时不补造结论。

明确的选择直接转成结构化结果，自由备注由当前窗口模型处理；选择与备注含义冲突时，先在当前窗口明确。仅应用已勾选的对局，已入库对局的不同选择按修订处理。入库和发布按用户另行授权的范围执行。

## 完成检查

检查本次页面：截图可看且可放大、12席对应正确、对局流程和票型顺序符合呈现规范、复盘区间正确；唯邻是从座位表分开显示物理底牌与个人阵营，首夜排列不冒充已核睁眼顺序，空守用中文表达，神职技能影响仅附在实际发动的技能事项，确认交牌显示并终止流程、交牌者未知时不补座位；悍跳人默认未选择、成功控件选人后启用；“本局无人悍跳”可勾选、取消，刷新与导入导出能往返全席`no`；草稿恢复、意见导入导出和桌面/手机显示可用。发布验收时对照[同一详细呈现规则](10_对局信息呈现规范.md#neighbor-puppet-display)核对API与页面顺序；单局裁定不推广。完成相关检查后交付。

唯邻是从样例逐项核对：S22 2026-08-07第2局（BV1pSuN62Ekr）显示12号大卫空守、第2天平安夜后狼人交牌并终止流程；S21 2026-03-04第2局（BV1SMPqzjEe6）不显示导入器英文占位备注，同时保留实际拍刀目标与结算，未知内容仍留待核。两项仅复核各自单局，不据此推广夜序或拍刀规则。
